# 分词器（Tokenizer）详解

> 组件二：分词 | 关联代码：[microgpt.py 第2部分](../microgpt.py#L70-L95)

## 通俗解释

神经网络是台"计算器"，它只认识数字，不认识字母。所以在文字进入模型之前，必须先把文字翻译成数字——分词器就是这个"翻译官"。

microgpt 的翻译规则简单到不能再简单：**26 个小写字母，一个字母一个编号**。

```text
a → 0,  b → 1,  c → 2,  ...,  z → 25
```

另外还有一个特殊编号 **26，叫 BOS**（Beginning of Sequence，序列开始标记）。它就像一句对话的开场哨声："注意，一个新名字要从这里开始了！" 训练时每个名字两边都加上它：

```text
emma  →  [26, 4, 12, 12, 0, 26]
          BOS  e   m   m  a  BOS
```

模型于是学会两件事：看到 BOS 表示"开始取名"，生成 BOS 表示"这个名字取完了"。

## 专业解释

### 字符级分词

分词形式化地是一个双射函数 $\text{enc}: \Sigma \to \{0, \dots, V-1\}$，microgpt 通过：

```python
uchars = sorted(set(''.join(docs)))   # 对字符集排序，建立确定性映射
BOS = len(uchars)                      # BOS 占用最后一个 id
vocab_size = len(uchars) + 1           # 词表大小 V = 27
```

排序保证了映射的**确定性**：同样的数据集永远得到同样的字符→id 对应关系，这是可复现性的前提。

### BOS 与语言建模的边界

BOS 解决了语言建模中的**文档边界问题**。若不加边界标记，模型无法区分"这个 token 是文档开头"和"这个 token 接着上一篇"。给每个文档两侧包裹 BOS 后，序列上的联合概率可以完全分解为条件概率链：

$$p(d) = \prod_{t=1}^{T} p(x_t \mid x_{<t}, \text{BOS})$$

这使模型学到了显式的"开始生成/结束生成"行为，推理时 BOS 既作为起始 prompt，也作为终止符（stop token）。

### 为什么生产系统用 BPE 而不用字符级

字符级分词的缺点是**序列长、上下文稀疏**：英文单词平均 5 个字符，同样内容要多消耗约 4 倍的序列长度，注意力计算量按长度平方增长。BPE（Byte Pair Encoding）通过在语料上迭代合并高频字节对，学习出 5 万~10 万规模的子词词表，使常见词（如 "the"）压缩为单 token，稀有词回退为字符片段——在压缩率与覆盖率之间取得平衡。

| 对比 | 字符级（microgpt） | BPE（GPT-4 等） |
|------|--------------------|-----------------|
| 词表大小 | 27 | 约 10 万 |
| "emma" 的 token 数 | 4 | 1 |
| 序列长度 | 长 | 短（省 3~4 倍算力） |
| 未登录词处理 | 天然支持 | 回退到字节/字符 |
| 实现复杂度 | 3 行代码 | 需要 BPE 合并表训练 |

## microgpt 中的关键取舍

- 词表大小直接决定输出层维度（27 维 logits），也决定了随机基线损失：$-\log(1/27) \approx 3.3$
- `uchars.index(ch)` 是 $O(V)$ 查找，教学可接受；生产实现用哈希表达到 $O(1)$
- 字符集是**从数据推导的**，换数据集（如中文古诗）时无需改任何代码，分词器自动适应
