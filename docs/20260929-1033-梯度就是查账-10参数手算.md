# 梯度就是查账：一个 10 个参数的手算例子

> 面向还没看懂「反向传播 = 查账」的同学。
> 全文只用加减乘除，一步一步算，不跳步。
> 算完之后你会得到一张表：**10 个参数，每个参数的「责任」各是多少**。

---

## 〇、先看结论（防迷路）

一句话：**梯度 = 每个参数各自对「预测错了多少」负的责任。**

本文例子算完后，10 个参数的责任表如下（推导过程在后面，先有个印象）：

| 参数 | w1 | w2 | w3 | w4 | w5 | w6 | w7 | w8 | w9 | w10 |
|------|----|----|----|----|----|----|----|----|----|-----|
| 初始值 | 0.5 | 1 | -1.5 | 2 | 0.2 | 0.1 | -0.1 | 0.3 | 0 | 2 |
| 责任（梯度） | -5.67 | -2.835 | **+1.26** | -1.26 | -29.4 | -4.2 | -14.7 | -4.2 | -2.1 | -3.15 |

**读表方法**：责任是负数 = 「把它拧大，loss 会变小」（往右拧）；正数 = 「把它拧小，loss 会变小」（往左拧）。数字大小 = 这个旋钮对错误的贡献份额。

---

## 一、「查账」三条规则（全文只用这三条）

想象你开了一家奶茶店，店里有一排**旋钮**（就是模型的 10 个参数）。拧不同的位置，今天预测的销量不一样。你的目标是让预测尽量贴近真实。

「算梯度」就是在回答一个问题：

> **每个旋钮，各自对「预测错了多少」负多大责任？该往哪边拧、拧多少？**

| 规则 | 人话 | 对应数学 |
|------|------|----------|
| **规则 1：先记账** | 每算出一个新数字，顺手记下它是由谁、按什么比例算出来的 | 局部导数（local gradient） |
| **规则 2：往回查** | 从最终的错误（loss）出发，挨个数字问：「你的责任，该分给谁？分多少？」 | 链式法则：下游责任 × 本步斜率 |
| **规则 3：共用的要加** | 一个数字被好几处共用，每处传来的责任**相加**，写 `+=` | 多元情况下的梯度累加 |

全程只需要记住一句话：

> **乘法接力（责任沿路径相乘），共用的叠账（多路径相加）。**

## 二、例子设定：10 个旋钮的迷你预测机

**场景**：根据两个线索预测奶茶店今天销量（杯）：
- 线索 1：`x0 = 2`（比如气温分，越高生意越好）
- 线索 2：`x1 = -1`（比如「是不是周末」的编码）
- 今天真实销量：`y = 5`

**10 个旋钮（参数）初始值**：

| 旋钮 | w1 | w2 | w3 | w4 | w5 | w6 | w7 | w8 | w9 | w10 |
|------|----|----|----|----|----|----|----|----|----|-----|
| 初始值 | 0.5 | 1 | -1.5 | 2 | 0.2 | 0.1 | -0.1 | 0.3 | 0 | 2 |

**机器结构**（故意很小，小到能手算）：

```text
第一层（两个「中间工」）：
  h1 = w1*x0 + w2
  h2 = w3*x1 + w4

两个中间工碰头：
  h3 = h1 * h2

第二层：
  o1 = w5*h3 + w6
  o2 = w7*h3 + w8*h1 + w9      ← 注意：h3 和 h1 都被用了两次（后面要叠账）

汇总出预测：
  pred = w10*o1 + o2

算错误：
  loss = 0.5 * (pred - y)^2    ← 平方损失：差半分娘子
```

数一下参数：w1、w2、w3、w4、w5、w6、w7、w8、w9、w10 —— 正好 **10 个旋钮**。

## 三、前向传播：边算边记账

按顺序算一遍。每算出一个新数字，**同时记下它的账本**（它由谁、按什么比例凑成）。

### 3.1 两个中间工

**节点 h1**：

```text
h1 = w1 * x0 + w2 = 0.5*2 + 1 = 2
h1 的账本：「我由两笔账凑成 —— w1（斜率=x0=2）、w2（斜率=1）」
```

**节点 h2**：

```text
h2 = w3 * x1 + w4 = (-1.5)*(-1) + 2 = 3.5
h2 的账本：「我由两笔账凑成 —— w3（斜率=x1=-1）、w4（斜率=1）」
```

> 加法的账最好记：`a+b` 里，a 的斜率永远是 1，b 的斜率永远是 1。

### 3.2 碰头相乘

**节点 h3**：

```text
h3 = h1 * h2 = 2 * 3.5 = 7
h3 的账本：「我由两笔账凑成 —— h1（斜率=h2=3.5）、h2（斜率=h1=2）」
```

> 乘法的记账口诀：`a*b` 里，查 a 的账用 b 的值当斜率，查 b 的账用 a 的值当斜率。
> 为什么？因为 b=3.5 时，a 每多 1，乘积就多 3.5。

### 3.3 第二层

**节点 o1**：

```text
o1 = w5 * h3 + w6 = 0.2*7 + 0.1 = 1.5
o1 的账本：「w5（斜率=h3=7）、w6（斜率=1）」
```

**节点 o2**（注意：它同时吃了 h3 和 h1）：

```text
o2 = w7*h3 + w8*h1 + w9 = (-0.1)*7 + 0.3*2 + 0 = -0.7 + 0.6 = -0.1
o2 的账本：「w7（斜率=h3=7）、w8（斜率=h1=2）、w9（斜率=1）」
```

### 3.4 汇总与损失

**节点 pred**：

```text
pred = w10*o1 + o2 = 2*1.5 + (-0.1) = 2.9
pred 的账本：「w10（斜率=o1=1.5）、o2（斜率=1）」
```

**节点 loss**：

```text
loss = 0.5 * (pred - y)^2 = 0.5 * (2.9-5)^2 = 0.5 * 4.41 = 2.205
loss 的账本：「pred（斜率 = pred - y = 2.9 - 5 = -2.1）」
```

> 平方损失的变化率有个简洁结论：`0.5*(pred-y)^2` 对 pred 的变化率 = `pred - y`。
> （预测比真实小 2.1，所以斜率为负：把 pred 拧大一点，loss 会变小。）

### 3.5 前向账本汇总表

| 节点 | 数值 | 账本：子节点（斜率） |
|------|------|----------------------|
| h1 | 2 | w1（2）、w2（1） |
| h2 | 3.5 | w3（-1）、w4（1） |
| h3 | 7 | h1（3.5）、h2（2） |
| o1 | 1.5 | w5（7）、w6（1） |
| o2 | -0.1 | w7（7）、w8（2）、w9（1） |
| pred | 2.9 | w10（1.5）、o2（1） |
| loss | 2.205 | pred（-2.1） |

这张表就是 microgpt 里 `Value` 类存的东西：`data`（数值）、`_children`（子节点）、`_local_grads`（斜率）——一行不差。

## 四、查账总起点：两个已知责任

**1）loss 对自己的责任 = 1**

「责任」的纪律：loss 就是错误本身，它自己动 1 份，错误就动 1 份，所以变化率 = 1。这是全表唯一的起点（行话叫「种子」，seed）。

**2）pred 的责任 = -2.1**

从 loss 的账本往前推一步：

```text
pred 的责任 = loss 的责任 × 账本斜率 = 1 × (-2.1) = -2.1
```

含义：pred 每增大 1，loss 减少 2.1。确实，pred 现在 2.9，真实 5，往上抬是对的。

---

## 五、一步一步往回查账

每查一个节点，套路都一样：

```text
本节点的责任（已知）
  × 账本上记的斜率
  = 分给对应子节点的责任
```

### 第 1 查：pred（责任 -2.1）

查它的账本：w10（斜率 1.5）、o2（斜率 1）。

```text
w10 的责任 = -2.1 × 1.5 = -3.15   ← 是旋钮，定稿！
o1 的责任  = -2.1 × 2   = -4.2
o2 的责任  = -2.1 × 1   = -2.1
```

### 第 2 查：o1（责任 -4.2）

查它的账本：w5（斜率 7）、w6（斜率 1）。

```text
w5 的责任 = -4.2 × 7 = -29.4      ← 定稿！
w6 的责任 = -4.2 × 1 = -4.2       ← 定稿！
h3 收到第 1 笔：-4.2 × w5 = -4.2 × 0.2 = -0.84   （先记在黑板上，先不加）
```

注意「查账」和「记账」的区别：责任是**上游节点的数值**（data），斜率是**参数/子节点的数值**（data），两个都是现成的数，查表即可。

### 第 3 查：o2（责任 -2.1）

查它的账本：w7（斜率 7）、w8（斜率 2）、w9（斜率 1）。

```text
w7 的责任 = -2.1 × 7   = -14.7    ← 定稿！注意 w7=-0.1 不影响这里：斜率看的是被乘的 h3=7
w8 的责任 = -2.1 × 2   = -4.2     ← 定稿！
w9 的责任 = -2.1 × 1   = -2.1     ← 定稿！
h3 收到第 2 笔：-2.1 × w7 = -2.1 × (-0.1) = +0.21
h1 收到第 1 笔：-2.1 × w8 = -2.1 × 0.3    = -0.63   （先记黑板）
```

### 第 4 查：h3（两笔账都到齐了）

h3 被 o1 和 o2 两处共用 —— 规则 3：**加**。

```text
h3 的责任 = 第1笔 + 第2笔 = (-0.84) + 0.21 = -0.63
```

再继续分：查 h3 的账本：h1（斜率 3.5）、h2（斜率 2）。

```text
h1 收到第 2 笔：-0.63 × 3.5 = -2.205
h2 的责任 = -0.63 × 2 = -1.26        ← 定稿！
```

### 第 5 查：h1（两笔账都到齐了）

h1 被 o2（直接）和 h3（乘进去的）两处共用 —— 相加：

```text
h1 的责任 = (-0.63) + (-2.205) = -2.835
```

查 h1 的账本：w1（斜率 2）、w2（斜率 1）。

```text
w1 的责任 = -2.835 × 2 = -5.67   ← 定稿！
w2 的责任 = -2.835 × 1 = -2.835  ← 定稿！
```

### 第 6 查：h2（责任 -1.26）

查 h2 的账本：w3（斜率 -1）、w4（斜率 1）。

```text
w3 的责任 = -1.26 × (-1) = +1.26   ← 定稿！全表唯一的正数
w4 的责任 = -1.26 × 1    = -1.26   ← 定稿！
```

### 查账完成

10 个旋钮全部拿到了责任，一个不落。这就是「4192 个旋钮各自的责任浮出水面」的完整演示——区别只在那张表更长。

## 六、汇总与解读

| 参数 | 数值 | 责任（梯度） | 拧大它会怎样 | 拧多大合适（lr=0.01 演示） |
|------|------|--------------|--------------|---------------------------|
| w1 | 0.5 | -5.67 | loss 变小 | 0.5 + 0.0567 = 0.5567 |
| w2 | 1 | -2.835 | loss 变小 | 1 + 0.02835 = 1.028 |
| w3 | -1.5 | **+1.26** | loss 变大 | -1.5 - 0.0126 = -1.5126 |
| w4 | 2 | -1.26 | loss 变小 | 2 + 0.0126 = 2.0126 |
| w5 | 0.2 | -29.4 | loss 变小 | 0.2 + 0.294 = 0.494 |
| w6 | 0.1 | -4.2 | loss 变小 | 0.1 + 0.042 = 0.142 |
| w7 | -0.1 | -14.7 | loss 变小 | -0.1 + 0.147 = 0.047 |
| w8 | 0.3 | -4.2 | loss 变小 | 0.3 + 0.042 = 0.342 |
| w9 | 0 | -2.1 | loss 变小 | 0 + 0.021 = 0.021 |
| w10 | 2 | -3.15 | loss 变小 | 2 + 0.0315 = 2.0315 |

**更新公式**（往 loss 下降的方向走）：

```text
w 新 = w 旧 - lr × 责任
```

- 责任为负 → 减负 = 加 → 拧大。预测 2.9 < 真实 5，整体往上抬，符合直觉。
- w5 的责任最大（-29.4）：它出一点小错就被 h3 放大 7 倍，再往下传 —— 步子也最大。
- w3 是全表唯一「该拧小」的：xh1=-1 这个负线索让它走了反方向，账本会把这点自动纠出来。

> 真实训练里，不会所有旋钮共用同一个 lr（步子大小差太多），所以有 Adam 这样的优化器给每个旋钮单独调速 —— 但「往责任的反方向走」这个大方向不变。

## 七、我算对了吗？三种验证方法

**方法 1：符号直觉。** 10 个里 9 个负面 1 个正面，合理吗？预测 2.9 小于真实 5，大多数旋钮拧大能抬预测，方向一致。w3 走反是因为它乘的是 -1。符合账本规律。

**方法 2：数值验证（骗不了数学）。** 只拧一个旋钮一丁点，重算 loss，看变化比率是否等于表中的责任。

验证 w5（责任 -29.4）。把 w5 从 0.2 拧到 0.201（+0.001）：

```text
o1 = 0.201*7 + 0.1 = 1.507
pred = 2*1.507 - 0.1 = 2.914
loss = 0.5*(2.914-5)^2 = 0.5*4.351396 = 2.175698

loss 变化 = 2.175698 - 2.205 = -0.029302
比值 = -0.029302 / 0.001 = -29.3 ≈ -29.4  ✓
```

验证 w9（责任 -2.1）。把 w9 从 0 拧到 0.001：

```text
o2 = -0.7 + 0.6 + 0.001 = -0.099
pred = 3 - 0.099 = 2.901
loss = 0.5*(2.901-5)^2 = 0.5*4.405801 = 2.202900

比值 = (2.202900 - 2.205) / 0.001 = -2.1  ✓ 完全吻合
```

**方法 3：跑代码。** 用 microgpt 里的 `Value` 类搭同一个图，`loss.backward()` 后打印 10 个 `w.grad`，应当与本文表格完全一致（这正是 `p.grad` 里存的东西）。

## 九、FAQ

**Q1：为什么 loss 对自己的责任是 1？**
A：「责任」量的是「我动 1 份，最终错误动几份」。loss 就是最终错误本身，动 1 份错 1 份，变化率 = 1。它是唯一不需要别人告诉它的起点。

**Q2：加法和乘法的斜率分别是多少？**
A：`a+b`：对 a 恒为 1，对 b 恒为 1。
`a*b`：对 a 是 b，对 b 是 a（b=3.5 时，a 多 1，积多 3.5）。
特殊一个：`0.5*(pred-y)^2` 对 pred 的斜率 = `pred - y`。

**Q3：为什么共用的节点要相加，不取平均或只取最大？**
A：责任是「净贡献」。h3 变了，它同时从 o1、o2 两条路影响 loss，两条路的影响都真实存在，总责任就是两者之和。好比一个人同时给两个项目打工，他的总 KPI 是两个项目 KPI 之和。只取一条路就会漏账。

**Q4：为什么 `+=` 而不是 `=`？**
A：就是因为「共用」。h1 先收到 o2 传来的 -0.63，后又收到 h3 传来的 -2.205，如果用 `=`，先到的那笔就被后一笔冲掉了。用 `+=`，两笔都留。

**Q5：知道「斜率」就行了吗？为什么还要责任一级级传？**
A：斜率只回答「我直接影响上一级多少」；但要问到 loss（总账），必须一层层把下游责任传回来。单看局部永远不知道全局，这正是链式法则存在的意义。

**Q6：那为什么不「每个旋钮单独拧一拧，看 loss 变化」来算梯度？**
A：数值试拧 1 个旋钮要 1 次前向：10 个旋钮要 10 次，4192 个旋钮要 4192 次，且拧多少步长也有精度问题。查账是「1 次前向 + 1 次回溯」把全部旋钮一次算完 —— 这就是反向传播存在的全部理由。

```text
  w3 的责任 = -0.6 × x1 = -0.6 × (-1) = +0.6
  w4 的责任 = -0.6 × 1 = -0.6

汇总表（w10=3）：
| w1 | w2 | w3 | w4 | w5 | w6 | w7 | w8 | w9 | w10 |
|----|----|----|----|----|----|----|----|----|-----|
| -2.46 | -1.23 | +0.6 | -0.6 | -12.6 | -1.8 | -4.2 | -1.2 | -0.6 | -0.9 |
```

## 十一、一页纸回顾

1. **记账**：每个新数字都写下「我是谁 × / + 谁凑成的」——这就是 `_children` + `_local_grads`。
2. **种子**：loss 对自己的责任 = 1；预测差距 `pred - y` 是它交给 pred 的第一笔。
3. **查账**：责任 = 下游传来的责任 × 账本斜率；一路问到 10 个旋钮。
4. **叠账**：被共用的节点（h3、h1）要 `+=`，一笔都不能丢。
5. **拧旋钮**：`w -= lr × 责任`，往 loss 下降的方向走一步。
6. **验证**：拧一丁点看 loss 变化，比值必须等于算出的责任。

把这张纸上的流程在心里跑一遍、能复述，你就真的懂「梯度」了 —— microgpt 里的 `backward()`，无论查 10 本账还是 4192 本账，用的都是这一套。
