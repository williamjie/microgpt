# 训练 GPU 和推理 GPU 不一样吗？

> 系列阅读地图：上一篇 [20260923-1417-AI基础设施.md](20260923-1417-AI基础设施.md) 讲了 AI Infra 全景。这篇往下钻一层：同样叫 GPU，训练和推理两种活儿，为什么需求天差地别。
>
> 全文零公式，全部用生活比喻。

---

## 一、一句话回答

**硬件上它们可以是同一种 GPU（比如都是 H100），但干的活完全不同，吃的资源也完全不同。**

- **训练吃"算力 + 超大显存 + 多卡互联"**——像马拉松，跑几个月。
- **推理吃"显存带宽 + 显存容量"**——像百米冲刺 × 每天几亿次。

业界的经典概括：**训练是算力密集型，推理是带宽密集型。**

所以芯片厂商开始分化：训练首选 H100/B200 这种"全能重卡"，推理常用 H20、L40S 这类"算力被砍、显存和带宽拉满"的卡，甚至出现了 Groq、Cerebras 这类专攻推理的芯片——**因为两种工作负载的瓶颈根本不在同一个地方**。

---

## 二、为什么差别这么大？先看两件事在干什么

### 训练 = "学习 + 批改 + 改教材"

训练一个模型，每个 batch 数据要走三步：

1. **前向**：算出预测，跟答案对比
2. **反向**：算出每个参数该怎么改（梯度）
3. **更新**：优化器（如 Adam）按梯度改参数

关键在于：**每一步的中间结果都不能扔**。梯度要留着等反向用，优化器状态（Adam 的一阶、二阶动量）要一直挂着，每层激活值也要存着等反向传播回来用。

**比喻**：训练像一个老师带全班学生做错题本——不但要答题，还要把每一步的草稿、每道题的批注全部留存，回头还要翻出来逐项订正。**草稿纸（显存）消耗是天文数字。**

### 推理 = "考试 + 逐字作答"

推理只有前向，没有反向、没有参数更新。但有个特殊之处：它是**自回归**的——一个字一个字往外蹦，每生成一个字，都要**把全部模型参数从显存里读一遍**。

**比喻**：推理像考生答题——知识（参数）早就装进脑子里了，不用再改教材，但每写一个字都要**把整本教科书翻一遍**。翻书速度（显存带宽）就成了天花板，而不是脑子转得多快（算力）。

业界有句话特别精辟：

> **算力就是搬砖的力气，带宽就是运砖的路。** 训练砖运得少但每块都要砸得重；推理大部分时间花在运砖路上，力气再大也白搭。

## 三、资源消耗对比表

| 维度 | 训练 | 推理 |
|---|---|---|
| **每个 token 的计算量** | 每参数约 6~8 次浮点运算（前向+反向+优化器） | 每参数仅 2 次（只有前向） |
| **总计算量** | 万亿级 token，累计比单次推理高 4~6 个数量级 | 单次请求几百到几千 token |
| **显存构成** | 五件套：权重 + 梯度 + 优化器状态 + 激活值 + KV 缓存 | 三件套：权重 + 少量激活 + KV 缓存 |
| **显存大小**（7B 模型，FP16） | 仅模型状态约 **112 GB** | 约 **14 GB** 权重 + 2 GB KV |
| **通信需求** | 硬性要求：千卡 AllReduce 每秒搬 TB 级梯度，必须 NVLink + InfiniBand | 主要拼单卡带宽，不太依赖多卡互联 |
| **优化目标** | 吞吐最大（tokens/s），马拉松心态 | 延迟最小（首 token 快、吐字快），冲刺心态 |
| **精度** | FP16/BF16 起步，FP32 只留主副本 | 敢用 INT8/INT4 量化，砍掉一半以上显存 |
| **典型耗时** | 数周至数月 | 毫秒到秒级 |

**最扎眼的数字**：同一个 7B 模型，训练的显存需求是推理的 **6~8 倍**。这就是"训练卡"和"推理卡"分家的根本原因——一个要装下"教材 + 错题本 + 批注 + 草稿"，另一个只要装下"教材"。

---

## 四、推理的隐藏大户：KV Cache

推理显存里最反直觉的部分是 **KV Cache**（回忆我们的通俗版文档：KV Cache = 会议纪要）。

- 生成第 N 个字时，不用重算前 N-1 个字的注意力，直接查"会议纪要"——代价是这份纪要要一直占着显存。
- 它随 **并发人数 × 上下文长度** 线性膨胀。短对话时权重占大头；**长文本 + 高并发时，KV Cache 会反超权重，成为显存真正的无底洞**。

这也是推理扩容最常见的翻车点：只算"权重装不装得下"，没算"纪要本要多大书架"，结果上线一加并发就爆显存（OOM）。

另外推理分两段，瓶颈还不一样：

- **Prefill（读题）**：一次性处理你输入的全部提示词，并行度高，**拼算力**——像考生一目十行通读全卷。
- **Decode（写答案）**：一个字一个字往外蹦，每步计算量极小但要把全部权重搬一遍，**拼带宽**——算力单元大部分时间在干等数据。

业内一句话：**Prefill 是算力瓶颈，Decode 是带宽瓶颈。加卡不一定有用，方向对了才有用。**

---

## 五、所以厂商造卡分了两条路线

| | 训练向 GPU | 推理向 GPU |
|---|---|---|
| 代表型号 | H100 / H200 / B200 | H20 / L40S / 各家推理 ASIC |
| 硬件重点 | 高 FP8/TF32 算力 + 超大 HBM + NVLink 多卡互联 | 大显存 + 高带宽 + 低延迟 + 量化支持 |
| 典型取舍 | 什么都要，什么都拉满，贵 | 砍掉大半算力，保住显存和带宽，便宜 |
| 典型场景 | 千亿~万亿参数预训练 | 70B 模型线上服务、7B 模型高并发 |

典型例子：**H20 的 FP16 算力只有 H100 的零头，但显存和带宽够用**——放在推理场景反而性价比更高。就像物流行业：干线运输用重卡（训练），末端配送用电动车（推理），拿重卡去送快递纯属浪费。

顺带一提微调（Fine-tuning）夹在中间：要反向传播，但通常只更新 LoRA 小参数，资源比全量训练小 1~2 个数量级，比推理多一份梯度开销——算是"骑电动车拉货"。

## 六、回到 microgpt：一行代码就能看出区别

microgpt 的代码里就有这个分界线：

| 工业场景 | microgpt 对应 |
|---|---|
| 训练：`logits = model(x)` → 算 loss → `loss.backward()` → `optimizer.step()`，梯度、优化器状态全程驻留显存 | `train()` 循环 |
| 推理：`torch.no_grad()` 下 `generate()` 逐 token 采样，只要权重 + KV Cache，没有梯度 | `generate()` 函数 |

microgpt 之所以能用一块普通 CPU 训练，正是因为它"小"——17 层 Transformer、几千参数，训练显存的"五件套"加起来也不大。把它放大一万倍（千亿参数），五件套立刻膨胀到任何单卡都装不下，训练和推理的分裂就出现了。**不是模型变了，是账单变了。**

---

## 七、总结成三句话

1. **训练和推理可以是同一块 GPU，但瓶颈不同**：训练卡在算力和显存四件套，推理卡在显存带宽和 KV Cache。
2. **训练是马拉松，推理是每天跑几万次百米冲刺**——前者优化吞吐和容错，后者优化延迟和并发。
3. **所以芯片分化了**：训练买"全能重卡"，推理买"大显存电动配送车"，选错型号就是烧钱。
