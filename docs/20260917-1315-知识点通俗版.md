## 全书先讲一个总故事

microgpt 做的事，一句话概括：

> **给电脑看 3 万个人名，让它自己悟出"名字长什么样"，然后编出新名字。**

就像你看了几千部古装剧，闭着眼也能编一个"听起来像古代人"的名字。电脑做的事一模一样，只是它靠的是大量加减乘除，而不是"感觉"。

整个流程就是 7 步，后面所有知识点都挂在这条线上：

```text
① 拿到 3 万个名字 → ② 把字母变成数字 → ③ 让电脑能"从错误中学习"
→ ④ 搭一个神经网络 → ⑤ 反复练习 1000 轮 → ⑥ 练完开始编名字 → ⑦ 编出 karia 这样的新名字
```

## 第一站：数据（知识点 2、6 相关）

### 1. 数据集是什么？——"课本"

模型学习的唯一来源就是 `input.txt` 里的 3 万个名字。它没有词典、没有老师、没有常识，**全部认知都来自这个文件**。

所以如果你把文件换成 3 万个菜名，它就会编菜名；换成古诗，它就会编古诗。

**为什么选名字当课本？** 因为名字短、规律明显（辅音开头、元音穿插），笔记本 1 分钟就能练完，效果肉眼可见。

**小细节**：代码里 `random.shuffle(docs)` 是把课本顺序打乱。就像背单词不能总按字母顺序背，不然容易"背位置"而不是"背内容"。

## 第二站：分词器（知识点 3）

### 2. 为什么要分词？——"电脑不认字，只认数字"

电脑的芯片只会算数字，看到字母 "e" 它是懵的。所以要先发"编号"：

```text
a=0, b=1, c=2, ..., z=25, 还有个特殊的 26 号叫 BOS
```

**BOS 是什么？** 可以理解成一个"哨声"：

- 练习时，每个名字两边都吹哨：`"emma" → [哨声, e, m, m, a, 哨声]`
- 第一个哨声 = "新名字开始了！"；最后的哨声 = "名字说完了！"

模型学会了"听到哨声就开始取名、编到哨声就停"。这就是为什么它能自己知道一个名字什么时候编完。

**ChatGPT 也一样吗？** 一样，只是它用更聪明的"打包"方式（BPE）：把 "the" 这种常见词打包成一个编号，省时省力。microgpt 图省事，一个字母一个编号。

## 第三站：自动微分——全项目最核心的部分（知识点 4、5）

### 3. 梯度是什么？——"调味的手感"

想象你给一锅汤调味，盐多了还是少了，尝一口就知道该加还是该减。"尝一口 → 知道方向和幅度"，这个**方向和幅度**就是梯度。

模型里有 4192 个"调味旋钮"（参数）。每练一轮，我们都要知道**每个旋钮该往哪边拧、拧多少**。梯度就是答案。

#### 追问：4192 个旋钮，怎么同时知道每个该拧多少？

最笨的办法是**一个一个试**：把旋钮 1 拧一点，重算一遍总分；再试旋钮 2，又重算一遍……4192 个旋钮就要完整重算 4192 遍。就像给汤调味，尝一口只能知道"整体的咸淡"，想知道"每一味料各贡献了多少"，难道要单独重做 4192 锅汤？

其实不用。有一个关键观察：**模型里每一步运算的"敏感度规则"都是已知的**。就像你虽然不知道整锅汤的配方，但你知道盐、糖、醋各自的脾气：

- 加法：你多一点，结果就多一点（一比一传导）
- 乘法：你多一点，结果多"对方那么多"倍（3 × 4 = 12，3 变 4 则变 16，多 4，正好是对方 b 的值）
- ReLU：正数照传，负数直接掐断

模型不管多复杂，都只是这几种简单运算的**上万次串联**。每算一步，[Value 类](../microgpt.py#L155-L160)就把"这一步的敏感度规则"记在账本上。

于是判断梯度就变成了**查账**：

```text
从总分损失出发（它是唯一确定的起点，对自己敏感度=1）
→ 一步一层往回查："这步的敏感度 × 下游传来的责任" = 这步的责任（乘法接力）
→ 某个数字被几处共用？几份责任加起来（+= 叠账）
→ 查到最底层，4192 个旋钮各自的责任就全数浮出水面
```

**一句话总结**：不用试 4192 遍，因为"局部规则"人人皆知，"全局责任"可以沿着记账链条一次倒推算完。这就是反向传播，代价只相当于正向算两遍——这也是为什么全世界的模型都用这种方式求梯度。具体账本怎么记、责任怎么接力，往下看第 4、5 节。

### 4. Value 类是什么？——"会记账的数字"

**先搞清楚我们到底想回答什么问题。**

模型练完一轮，总分（损失）出来了。下一步要让每个旋钮都拧一点点，让下次总分变低。拧之前必须先回答：

> "把旋钮 a 往上拧一点点，总分是变好还是变坏？变多少？"

这个"变多少"，就是 a 的梯度。

**难点在哪？** 旋钮和总分不是直接相连的，中间隔着一长串运算：

```text
a=3 ──┐
      ├─→ c = a × b = 12 ──→ L = c × 5 = 60（总分）
b=4 ──┘
```

a 动一下，先影响 c，c 再影响 L——是**连锁反应**。就像问"你早上多睡 1 分钟，晚上到家会晚几分钟？"：多睡 1 分钟 → 出门晚 1 分钟 → 没赶上原班地铁 → 晚 10 分钟。每一段"晚多少"都好算，难的是把整条链算总账。

**Value 的办法：让每个中间结果随身带一张"小抄"。**

普通数字只记得结果，`Value` 算完还会多记一笔账。看迷你模型的两次记账：

**第一步：算出 `c = a × b`（a=3, b=4），c 的账本：**

| 账本条目 | 内容 |
|---|---|
| 结果 | 我是 12 |
| 来历 | 我是由 a 和 b 相乘得来的 |
| 小抄 | a 多 1 → 我多 4；b 多 1 → 我多 3 |

小抄怎么来的？口算：`3 × 4 = 12`，把 a 改成 4，变成 `4 × 4 = 16`，多了 **4**；把 b 改成 5，变成 `3 × 5 = 15`，多了 **3**。规律很简单：**乘法里，你的敏感度 = 对方的值**。

**第二步：算出 `L = c × 5`，L 的账本：**

| 账本条目 | 内容 |
|---|---|
| 结果 | 我是 60 |
| 来历 | 我是由 c 和 5 相乘得来的 |
| 小抄 | c 多 1 → 我多 5 |

**现在开始倒着翻账本（这就是反向传播）：**

问：a 多 1，总分 L 多多少？

```text
a 多 1 → c 多 4          （查 c 的小抄）
c 多 4 → L 多 4 × 5 = 20 （查 L 的小抄：c 每多 1，L 就多 5，现在多了 4 个 5）
答案：a 的梯度 = 20
```

再问：b 多 1，总分 L 多多少？

```text
b 多 1 → c 多 3          （查 c 的小抄）
c 多 3 → L 多 3 × 5 = 15 （还是那本 L 的账）
答案：b 的梯度 = 15
```

看到了吗？两个旋钮，各问一遍，**全靠翻小抄，一次实验都没重做**。真实模型里就是把这个动作重复几万次，4192 个旋钮的梯度就这样全部翻出来。

**所以 Value 类的本质一句话：一个自带小抄的数字。** 它知道自己等于多少、由谁算来、以及"上游动我一下，我会变多少"。整个模型训练时，前向传播就是"一路做账"，反向传播就是"倒着翻账"。对应代码见 [Value 类](../microgpt.py#L119-L160)。

### 5. 反向传播是什么？——"查账倒推责任"

比赛输了（损失很高），教练要复盘：谁的责任大？

- 方法：从结果往回一层层查，每层看"这一步让结果变化了多少"（这就是链式法则，其实就是**乘法接力**）
- 如果一个数字被用了两次，两份责任要**加起来**算总账（这就是代码里的 `+=`）

最神奇的是：4192 个旋钮的责任，`loss.backward()` **一行代码全部算完**。PyTorch 里那个大名鼎鼎的 `backward()`，干的就是这件事——这里是它的"手工原始版"。

#### 追问：每个参数的梯度都算出来了，然后拿它干什么？

梯度只是**诊断报告**，还不是**治疗动作**。拿到 4192 份报告后，下一步才是真正动手拧旋钮。最朴素的拧法就一行：

```text
旋钮新位置 = 旧位置 - 学习率 × 梯度
```

**为什么是减号？** 回看第 4 节的例子：a 的梯度是 20，意思是"a 多 1，总分多 20"。总分涨 = 变差，说明往这个方向拧是错的，所以要往**反方向**拧。永远减去梯度 = 永远朝"总分下降"的方向走。这也是"梯度下降"这个名字的由来：梯度告诉你哪边是上坡，你偏往下坡走。

拿例子真拧一遍：a 旧值 3，梯度 20，学习率取 0.01：

```text
a 新位置 = 3 - 0.01 × 20 = 2.8
```

4192 个旋钮每个都这样拧一点点，下一轮的总分就会比这一轮低一点。重复 1000 轮，就得到了那条下降曲线：**loss 从 3.3 一路降到 2.37**（见第 18 节）。

不过实际训练不会拧得这么"笨"，它在两处做了升级：

1. **拧多快**：每步迈多大由学习率控制，后期还会主动迈小步（学习率衰减，第 20 节）
2. **怎么拧才聪明**：Adam 优化器给这个减法加了"惯性方向"和"自适应步长"（第 19 节）——但拆到底，骨架还是上面那行减法

下面把这两处升级都拆开看。

**升级一：学习率——"每步迈多大"**

上面例子里的 0.01 不是随便编的，正好就是本项目代码里真实的学习率（[microgpt.py](../microgpt.py#L634) 里 `learning_rate = 0.01`）。

学习率为什么这么重要？可以用**淋浴调水温**来感受：

- **太大**：往烫的方向猛拧半圈——一下烫死；再猛拧回来——一下冻死，永远在烫和冻之间来回跳，水永远调不好。放到模型上：步子太大，一步直接跨过谷底冲到对面山坡，loss 上蹿下跳甚至越训越大。极端点算一下：学习率取 1，a 新位置 = 3 − 1 × 20 = **−17**，一步就从"偏高"拧到了"严重过头"。
- **太小**：每次只敢拧一丝丝，半天水都不热。放到模型上：a 只挪到 2.998，走 1000 轮也下不了山，白烧算力。
- **所以取"中间"**：小步快走，既稳又不磨蹭。0.01 就是这种"每步只动百分之几"的温和步幅。

本项目还叠加了**衰减**：`lr_t = learning_rate × (1 − step / 1000)`——训练越到后面步子越小（第 20 节的"先快走后碎步"）。

**升级二：Adam——给那行减法装上"两本流水账"**

笨办法有两个毛病：一是**梯度抖一下就跟着偏**（单次梯度带噪声，像被一块石头绊了就改道）；二是**大梯度旋钮被拖着狂奔、小梯度旋钮在爬**（步子被梯度大小绑架）。

Adam 给每个旋钮单独记两本流水账：

| 流水账 | 记什么 | 像什么 |
|---|---|---|
| **m（动量）** | 最近多次梯度的**平均**（本项目记约最近 7 步，beta1=0.85） | 下山不看脚下这一步，看**最近几步的整体走向**，不被一块石头绊偏 |
| **v（路况）** | 最近多次梯度**平方**的平均（本项目记约最近 100 步，beta2=0.99） | 这段路**颠不颠**：一直大起大落 → 迈小步；一直平缓 → 迈大步 |

然后每步真正执行的，还是那行减法，只是把"梯度"换成了"m ÷ √v"：

```text
旋钮新位置 = 旧位置 - 学习率 × m / √v
```

**方向看 m（惯性），步幅看 √v（路况）**——分子管往哪走，分母管走多远，两个毛病一次治好。

拿第 4 节的 a 真算一遍（第一步，梯度 20）：

```text
m ≈ 20（第一笔账就是它自己）    v ≈ 20² = 400    √v = 20
步长 = 0.01 × 20 / 20 = 0.01
a 新位置 = 3 - 0.01 = 2.99
```

注意一个有意思的现象：**不管梯度是 20 还是 2000，Adam 第一步的步长都约等于学习率本身**（分子分母约掉了）——它把"迈多大"从"梯度多大"里彻底解耦了。这就是 Adam "几乎不用调参就很好用"的真正原因。

（小注：m、v 从 0 起步时前几步的估计会偏小，代码里有个"偏差修正"把估计放大回去，见 [microgpt.py](../microgpt.py#L706-L713) 的 m_hat / v_hat，不影响上面的大逻辑。）

**追问的追问：4192 个旋钮一起拧，凭什么保证总分真的变小？**

这个疑问问到了梯度下降的命门。前面每份梯度报告都有个**隐含前提：其他 4191 个旋钮都不动**。可实际是全部一起拧，影响会互相"串门"。那凭什么是安全的？拿第 4 节的例子真算一遍，串门项能算出来：

总分 `L = a × b × 5`，a、b 各往回拧 0.01（a: 3→2.99，b: 4→3.99）：

```text
按两份独立报告预测：降 20×0.01 + 15×0.01 = 0.35
实际：L 从 60 变 59.6505，降了 0.3495
差的那 0.0005 就是"串门项"（≈ 5 × 0.01 × 0.01）
```

串门项比主项小了 **700 倍**。规律就在这里：**串门项是"小步 × 小步"的级别，步子够小，它就小到可以无视**——这是梯度下降能成立的真正地基，也是"学习率必须小"最根本的数学原因（不只是"求稳"）。

反过来看步子大了会怎样：各拧 1（a→2，b→3），预测降 35，实际只降 30——串门项吃掉了 5，从"九牛一毛"变成了"七分之一"。步子再大，还可能"各自的最优方向"叠加起来把你弹上对面山坡——这就是 loss 震荡的来源，也是学习率不能大的第二个原因。

还有一层：**拧完一步，所有小抄立刻过期**。梯度只在你拧之前那一瞬间成立，拧完之后的"地形"已经变了。所以闭环里 `backward()` 每一轮都要重新跑——不是流程需要，是数学必须。

所以严谨的说法是：**梯度下降不保证每一步都变小，只保证"小步 + 朝下坡方向 + 每步重新看地图"时，大方向必然向下**。再叠加每轮换名字带来的噪声，所以 loss 曲线从来不是直线下降，而是**锯齿形下降**——盯趋势，别盯单点。

**追问的三问："总损失变小"和"梯度"到底是怎么连起来的？**

前面一直在说单个旋钮，现在把镜头拉远，看"全体拧一遍 → 总分下降"这条因果链是怎么接上的。关键只有一句话：

> **总损失的变化 ≈ 每个旋钮的变化 × 它自己的梯度，全部加起来。**

再把拧旋钮的规则（每个旋钮都拧 −学习率 × 梯度）代进去：

```text
每个旋钮贡献的变化 = 梯度 × (−学习率 × 梯度) = −学习率 × 梯度²
```

盯住这个形式：**一个数的平方，加个负号**。平方永远 ≥ 0，加负号永远 ≤ 0——所以**每个旋钮的贡献都是"降"或"不动"，4192 个加起来必然是降**。"每个旋钮朝自己梯度的反方向拧"和"总损失下降"之间，就是这样用一道加法连起来的。拿 a、b 验证：

```text
ΔL ≈ 20 × (−0.01) + 15 × (−0.01) = −0.35
实际 ΔL = −0.3495（差的就是上一节算的串门项）
```

**画面感：蒙眼下山。** 把所有旋钮位置的组合想成一片山谷：位置越低，loss 越小（4192 维画不出来，但二维山谷同理）。你蒙着眼站在坡上，脚底能感觉出"哪边更陡"（梯度），于是朝低处挪一小步；地形变了，再感觉一次，再挪一步。"拧所有参数"不是 4192 件独立的事，而是**整个身体往低处挪**——每个坐标都动了，但合成起来就是一步下山。

**那模型是想把 loss 变成 0 吗？——想，但永远到不了。**

loss = 0 意味着对每个名字的每个字母都 100% 确定。但课本里本来就有"真随机"：同样是 "emm"，下一个字母可能是 a 也可能是 o——再聪明的模型也只能说"60% 是 a"。猜 a 已经是最优了，可那 40% 的惊讶**谁也消不掉**——这是数据本身的噪声，不是模型的错（ChatGPT 面对人类语言同样如此）。

再叠加两点：4192 个旋钮容量有限，记不全 3 万个名字的所有细节（详见 [20260917-1320-容量上限.md](20260917-1320-容量上限.md)）；练习步数也有限。所以真实目标不是 0，而是**压到这片课本的理论下限**。本项目 loss 从 3.3（纯瞎猜，27 选 1 的惊讶度）降到 2.37 后不再明显下降——剩下的部分，大半就是那种"消不掉的随机性"。

一句话收束：**梯度负责"每一步朝哪拧、拧多少"，损失负责"评判这一步走得对不对"；训练就是把评判信号一步步喂回拧旋钮的动作，直到压到数据允许的最低点。**

**追问的四问：4192 个旋钮一起拧，为什么不会互相"抵消"？**

先拆一个常见误会："所有参数都减低"其实不准确。看梯度符号：梯度为正的旋钮（如 a、b）**数值调小**，梯度为负的旋钮**数值调大**——参数有升有降。真正"全体一致"变小的只有一样东西：**loss**。

那"抵消"呢？抵消的意思是：一个旋钮的变化让 loss 降，另一个让 loss 升，一加一减等于白干。要发生抵消，队伍里必须有人做出**正贡献**。而回头看上一节推出来的那个形式：

```text
每个旋钮的贡献 = −学习率 × 梯度²
```

**无论梯度是正、是负、是大、是小，平方永远 ≥ 0，再加负号，这一项永远 ≤ 0。** 也就是说，抵消所需要的"正贡献"在这个更新规则里**结构性地不存在**——不是运气好没发生，是数学上写死了不可能。

拿一个梯度为负的旋钮验证。假设还有第三个旋钮 d，梯度是 −10（意思是 d 多 1，总分少 10，说明 d 该加大）。拧法照旧：

```text
d 的变化 = −0.01 × (−10) = +0.1   （参数值变大！）
d 的贡献 = (−10) × 0.1 = −1.0     （loss 照样降）
合起来：ΔL ≈ −0.35（a、b）− 1.0（d）= −1.35，全员皆"降"，无一抵消
```

a 降、d 升——参数一动一静，但对 loss 的贡献全是负的。**方向相反 ≠ 抵消**；恰恰相反，"各自朝自己梯度的反方向拧"正是每个人都被单独算过账的表现。

什么时候会真的抵消？如果所有人按**同一个**固定量拧（比如全体 +0.01，不看各自的梯度），梯度一正一负就会真抵消——像拔河，一半人往东一半人往西，白使劲。梯度下降的全部聪明之处就在这里：**每人按自己的梯度走，白费劲在数学上被排除**。

诚实补充（深度部分）："单步内不抵消"不等于"永不回调"。跨多步看，今天拧的某个旋钮明天可能被部分拧回来——因为串门项和地形在变，这正是 loss 曲线呈锯齿的原因；步子太大时串门项为正，甚至会吃掉总降幅。所以"不抵消"的准确适用范围是：**小步长 + 单步内（一阶近似）**。另外 Adam 也不破坏这个性质：m 只平滑方向、不改符号，每项贡献 ≈ −学习率 × m²/√v，同样永远非正。

到这里，一轮训练就形成了完整闭环：

```text
前向做账（猜下一字，算总分）→ 反向翻账（backward() 算出全部梯度）
→ 按梯度拧旋钮（Adam 更新参数）→ 梯度清零 → 换下一个名字重来
```

（"重来"两个字是关键：每拧一步小抄就全部过期，所以每一轮都要重新做账、重新翻账。）

## 第四站：搭模型（知识点 6~16）

### 6. 参数为什么不能全是 0？——"合唱团不能所有人唱同一个音"

如果 4192 个旋钮初始位置全一样，它们学东西时步调永远一致，永远学不出分工。所以要用**小随机数**起步，让每个人先有点不同，之后各自往不同方向成长。

### 7. 线性变换是什么？——"打分器"

模型里最常用的动作：拿一组权重去给一个向量"加权打分"。可以想象成 16 个评委，每人按自己的偏好（权重）给选手（输入）打分，最后汇总。

模型里所有"学到的知识"，本质都存在这些权重里。

### 8. Softmax 是什么？——"把分数变成百分比"

模型会输出 27 个分数（对应 27 个编号），softmax 把它们变成**加起来等于 100% 的概率**：

```text
分数 [3.2, 1.1, 0.5, ...] → 概率 [70%, 15%, 8%, ...]
```

分数差距越大，百分比越"一边倒"（模型很笃定）；差距小就接近均分（模型在犹豫）。

**代码里的减最大值是什么鬼？** 纯粹是防止数字太大算爆（e 的 1000 次方会溢出），先全体减去最大值，结果不变但更安全。像"先把所有温度都减去一个基准再比较"。

### 9. RMSNorm 是什么？——"校准音量"

数据在模型里传来传去，音量可能越来越大（爆音）或越来越小（没声）。RMSNorm 就是**每传一层就把音量校准回标准大小**，防止失控。它比老方法（LayerNorm）更简单省事，所以新模型（如 LLaMA）都用它。

### 10. 嵌入（Embedding）是什么？——"给每个字母发一张身份证"

编号 "5" 本身没有含义（第 5 号字母并不比第 4 号"多一点"什么）。所以给每个字母发一张 **16 个数字组成的身份证**，这些数字一开始随机，练着练着就有意义了——比如"经常出现在名字开头的字母"身份证会越来越像。

**位置嵌入**：光知道"是谁"不够，还得知道"排第几"。"em" 和 "me" 字母相同但意思不同。所以每个位置也有一张身份证。两张身份证**相加**，模型就同时知道"我是谁 + 我在哪"。

### 11. 注意力（Attention）是什么？——"环顾四周抄作业"（最重要！）

模型预测下一个字母时，会回头看前面的字母，判断**谁的信息最有用**，然后按比例"抄"过来。

三个角色演一台戏：

- **Q（查询）**："我在找什么？"——比如"前面出现元音了吗？"
- **K（钥匙）**："我这有什么？"——字母 e 说"我有元音信息"
- **V（内容）**："选我的话给你这些"——元音的具体信息

Q 和 K 对暗号（对得越准分越高），softmax 把分数变比例，然后**按比例混合各家的 V**。比如 [10%, 30%, 60%] 就是"第一个位置抄一点、第三个位置多抄点"。

**注意力是模型里唯一能"回头看"的地方**，所以它是整个模型最核心的部件。

**为什么要除以 √4（√head_dim）？** 防止打分太极端（全是 100% 或 0%），把分数压回温和区间。小技巧，但没有它训练会卡死。

### 12. 多头注意力是什么？——"4 个侦探分头查案"

把 16 维切成 4 份，每份 4 维，让 4 个"侦探"**各自独立**查不同的线索：

- 侦探 1：查"前一个字母是什么"
- 侦探 2：查"名字开头是什么"
- ……

最后把 4 份报告拼起来综合。分头查案能同时捕捉多种规律。

### 13. KV Cache 是什么？——"会议纪要"

模型一个字一个字地处理。处理到第 5 个字母时，前 4 个字母的信息如果每次都重新算一遍就太浪费了。所以把之前算好的 K 和 V **存起来当纪要**，新字母来了直接翻纪要。

这就是为什么 ChatGPT 生成到后面也不会越来越慢得离谱——不用每次从头重读全文。

### 14. 残差连接是什么？——"不做全盘推翻，只做增量修改"

每个部件处理完信息后，不是直接替换原内容，而是**"改出来的部分 + 原内容"相加**。

好处一：学习时梯度可以走"高速公路"直达底层，不会越传越弱（深网络能训练的关键）。
好处二：每个部件只负责"在原有基础上补充一点"，不容易把之前学的东西搞砸。

就像修改论文：不是全文重写，而是在原稿上批注补充。

### 15. MLP 是什么？——"独自消化"

注意力是"讨论"（跟别人交流），MLP 就是"各自回座位消化"：把 16 维信息先**放大到 64 维**（更大的草稿纸好写字），过一道 ReLU，再压回 16 维。

**ReLU 是什么？** 最简单的激活函数：正数照常通过，负数直接归零。像一道"只放行正数"的闸门。它带来了非线性——没有它，模型叠 100 层也只是一个简单的乘法，学不了复杂规律。

### 16. 整体结构一句话总结

```text
每个字母进模型后：
先"环顾四周抄作业"（注意力）→ 再"独自消化"（MLP）→ 输出对下一个字母的 27 个打分
```

微观模型和 ChatGPT 的结构一模一样，只是它只有 1 层、4192 个参数，ChatGPT 有上百层、千亿参数。

## 第五站：训练（知识点 17~21）

### 17. 训练目标是什么？——"看前文，猜下一字"

训练方式简单粗暴：遮住名字的下一个字母，让模型猜，然后对答案。

"emma" 拆成 5 道题：哨声→猜e、e→猜m、m→猜m、m→猜a、a→猜哨声。

**不需要人工出题**——每个名字自带答案，这就是"自监督"。ChatGPT 的预训练也是这个原理，只不过课本从名字换成了整个互联网。

### 18. 损失（loss）是什么？——"惊讶程度"

猜完对答案，用"**模型有多惊讶**"来打分：

| 模型给正确答案的概率 | 损失 | 含义 |
|---|---|---|
| 100% | 0 | 一点都不惊讶，完美 |
| 90% | 很小 | 有点意外，小扣分 |
| 1% | 很大 | 大吃一惊，重罚 |

训练的目标就是：**让模型对真实发生的事越来越不惊讶**（loss 越来越低）。

**记住两个数字**：训练前 loss≈3.3（27 选 1 纯瞎猜的水平），训练后≈2.37。从 3.3 降到 2.37，就说明模型真的学到东西了。以后你看任何模型训练，盯 loss 曲线就对了。

### 19. Adam 优化器是什么？——"聪明的老司机"

知道了每个旋钮的梯度（方向和幅度），下一步就是实际去拧。最笨的方法是"梯度说往左就往左走一步"。Adam 更聪明，它有两个记忆：

1. **动量 m**：记住最近几步的整体方向——像开车看方向盘的历史，不轻易被一阵颠簸带偏
2. **自适应步长 v**：记住每个旋钮的"路况颠簸程度"——一直很抖的旋钮迈小步，一直很稳的旋钮迈大步

所以 Adam = 方向看惯性 + 步长看路况，几乎不用调参就很好用，所以全世界训练大模型都在用它。

**一个必踩的坑**：每轮用完梯度必须**清零**（`p.grad = 0`），否则下一轮的新梯度会叠在旧账上，账越滚越乱，模型直接崩掉。

### 20. 学习率衰减是什么？——"先快走，后碎步"

学习率 = 每步迈多大。前期离目标远，大步流星；后期接近目标，小碎步微调，免得在终点附近来回冲过头。

代码里一行搞定：越接近 1000 步，步幅越小。

### 21. 一轮训练的完整节奏——"背单词四拍"

```text
① 拿一个名字，变数字，加哨声        （翻开一个单词）
② 逐字母猜下一字，算惊讶度          （尝试拼写）
③ 一行代码算出所有旋钮的责任        （对答案、复盘）
④ Adam 微调所有旋钮                 （修正记忆）
→ 换下一个名字，重复 1000 次
```

1000 次之后，"名字应该长什么样"就被压进了 4192 个旋钮的数值里。

## 第六站：生成（知识点 22~24）

### 22. 生成是什么？——"文字接龙"

练完之后开始编名字：吹哨（BOS）→ 模型给出 27 个概率 → **按概率掷骰子**抽一个字母 → 喂回去再抽下一个 → 直到模型自己吹"结束哨"。

```text
哨声 → k → ka → kar → kari → karia → 哨声（停）
```

**为什么掷骰子而不直接选概率最高的？** 永远选最高会千篇一律，还容易陷入死循环。按概率随机抽，才有多样性和"创造力"。ChatGPT 每个字也是这么抽出来的——这就是为什么同一个问题它每次回答不完全一样。

### 23. 温度（Temperature）是什么？——"创造力的旋钮"

温度控制骰子"偏"的程度：

| 温度 | 效果 | 像谁 |
|---|---|---|
| 接近 0 | 每次都选概率最高的 | 只说标准答案的学究 |
| 0.5（本项目） | 保守可靠 | 稳妥的起名顾问 |
| 1.0 | 原汁原味 | 本色出演 |
| 2.0 | 天马行空，常出怪名字 | 喝多的诗人 |

你在 ChatGPT 界面里看到的"温度"设置，背后就是这个公式，一模一样。

### 24. 幻觉是什么？——"一本正经地编"

模型编出 `karia`——数据集里没有，但听起来像真的。

重点来了：**这和 ChatGPT 编造错误事实，是同一个现象**。模型从没有"真假"的概念，它只负责"说统计上像话的话"。编名字时这叫创造力，编事实时这叫幻觉——同一个机制，不同场景不同后果。

这不是 bug，是"猜下一字"这个学习方式的天然属性。

## 第七站：从 microgpt 到 ChatGPT（知识点 1、25）

### 25. 差距在哪？——"食谱相同，餐厅规模不同"

| | microgpt | ChatGPT |
|---|---|---|
| 课本 | 3 万个名字 | 整个互联网 |
| 模型 | 1 层，4192 个旋钮 | 上百层，千亿旋钮 |
| 硬件 | 你的笔记本，1 分钟 | 几千张 GPU，跑几个月 |
| 额外训练 | 无 | 还有"礼貌课程"（人类反馈微调，让它学会好好说话） |

**但每一行的原理都一样**。GPU、分布式、量化……所有复杂技术都只是在让"同样的数学"跑得更快更多，没有一项改变了"猜下一字"这个核心。

所以 Karpathy 说："**这个文件就是完整的算法，其他一切都只是为了效率。**"

1. **课本**：3 万个名字（数据集）
