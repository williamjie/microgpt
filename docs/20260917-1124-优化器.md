# 优化器（Adam）与训练循环详解

> 组件五：优化器 | 关联代码：[microgpt.py 第6部分](../microgpt.py#L611-L723)

## 通俗解释

### 普通梯度下降 vs Adam

反向传播结束后，每个参数都拿到了梯度，告诉我们"往哪边调、调多少能降低损失"。最朴素的做法是普通梯度下降：

> 梯度说往左，我就往左走一步。步长 = 学习率。

但 Adam 更聪明，它给每个参数配了两个"记忆"：

1. **动量 m（惯性记忆）**：记住最近梯度的大方向。就像一个滚动的球——如果连续几步梯度都指向同一方向，它就沿这个方向加速前进，不会被单步噪声带偏
2. **自适应步长 v（地形记忆）**：记住每个参数最近的梯度波动程度。梯度一直很大的参数说明"这条路本来就陡"，就迈小步防止冲过头；梯度一直很小的参数就迈大步加速前进

可以类比**开车下山路**：普通梯度下降是闭着眼匀速走；Adam 是看着方向盘历史打向（动量）和当前路况颠簸程度（自适应步长），动态调整速度和方向。

### 偏差修正：新手上路的校准

m 和 v 从 0 开始累积，前几步的估计值偏小（像刚上路的司机对路况没经验）。偏差修正相当于给新手加一个"放大镜"：

$$\hat{m} = \frac{m}{1 - \beta_1^{t}}$$

训练步数 $t$ 越小，放大越厉害；随着 $t$ 增大，分母趋近 1，修正自动退出。

### 学习率衰减：先大步赶路，后小步微调

`lr_t = lr × (1 - step/num_steps)`：训练前期损失离最优很远，大步快走；后期接近最优点，小步精调，避免在谷底来回震荡。

## 专业解释

### 损失函数

训练目标为文档上的平均交叉熵：

$$L(\theta) = -\frac{1}{n} \sum_{t=1}^{n} \log p_\theta(x_{t+1} \mid x_{\le t})$$

随机基线为 $-\log(1/27) \approx 3.30$，训练 1,000 步后降至约 2.37。

### Adam 更新规则

对每个参数 $i$：

$$
\begin{aligned}
m_i &\leftarrow \beta_1 m_i + (1-\beta_1) g_i \\
v_i &\leftarrow \beta_2 v_i + (1-\beta_2) g_i^2 \\
\hat{m}_i &= m_i / (1-\beta_1^t), \quad \hat{v}_i = v_i / (1-\beta_2^t) \\
\theta_i &\leftarrow \theta_i - \text{lr}_t \cdot \frac{\hat{m}_i}{\sqrt{\hat{v}_i} + \epsilon}
\end{aligned}
$$

microgpt 的超参：$\text{lr}=0.01$（带线性衰减）、$\beta_1=0.85$、$\beta_2=0.99$、$\epsilon=10^{-8}$。相比常用值 $\beta_1=0.9$、$\beta_2=0.999$，这里动量更轻、二阶矩更灵敏——适合 1,000 步的短训练场景。

### 为什么必须清零梯度

`p.grad = 0` 出现在每个参数更新之后。因为反向传播中的梯度累加用 `+=`，若不清零，下一步的梯度会叠加在旧梯度上，等效于一个疯狂膨胀的动量，训练会迅速发散。PyTorch 用户熟悉的 `optimizer.zero_grad()` 做的就是这件事。

### 单文档 vs 大批次

microgpt 每步只喂 1 个名字（batch size = 1），梯度噪声大但成本极低，靠 1,000 步的循环平均掉噪声。生产训练每步喂几百万 token：一方面摊薄 GPU 通信开销，另一方面大 batch 的梯度估计更接近真实梯度方向，是 scaling law 的重要变量。此外生产系统还会叠加梯度累积、混合精度（bf16）、梯度裁剪等技巧——算法不变，全是效率工程。

### 训练循环骨架

```text
for step in range(1000):
    doc   = docs[step % N]                 # 1. 取文档，BOS 包裹，分词
    loss  = forward(doc)                   # 2. 逐位置前向，累计交叉熵
    loss.backward()                        # 3. 一次调用，4192 个梯度全部就位
    adam_update(lr_t)                      # 4. Adam 更新 + 梯度清零
```
