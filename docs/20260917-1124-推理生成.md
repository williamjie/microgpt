# 推理生成（Inference）详解

> 组件六：推理 | 关联代码：[microgpt.py 第7部分](../microgpt.py#L726-L783)

## 通俗解释

### 一个字一个字地"编"

训练完成后，模型脑子里已经装下了"英文名字的统计规律"。生成新名字的过程像一种文字接龙：

1. 喊一声"开始！"（输入 BOS）
2. 模型给出 27 个字母的概率，比如 "k" 20%、"a" 15%、"m" 10%……
3. **掷一个带偏的骰子**，按概率抽出一个字母，比如抽到 "k"
4. 把 "k" 喂回去，让模型接下一个字母
5. 循环，直到模型自己喊"完了"（生成 BOS）或达到最大长度

最终你得到 `karia` 这样一个数据集里**不存在**、但听起来很像真名字的新名字。

### 幻觉：同一个现象的两个名字

模型没有任何"真假"的概念，它只做一件事：**挑统计上合理的下一个 token**。"karia" 不是数据集里的名字，和 ChatGPT 自信地说出一条错误事实，在数学上是完全相同的现象——都是"听起来合理的补全"。这不是 bug，是"预测下一个 token"这个算法的固有属性。

### 温度：创造力的旋钮

温度（temperature）在 softmax 之前把 logits 除以它，控制骰子"偏"的程度：

| 温度 | 效果 | 类比 |
|------|------|------|
| 接近 0 | 永远选概率最高的（贪心解码） | 一个只说标准答案的学究 |
| 0.5（本脚本） | 分布变尖锐，保守可靠 | 稳妥的起名顾问 |
| 1.0 | 原始分布 | 随波逐流 |
| 2.0 | 分布变平，怪名迭出 | 喝多了的诗人 |

直觉：低温放大 logits 之间的差距，高温抹平差距。

## 专业解释

### 自回归解码

生成过程形式化为从模型分布中**序贯采样**：

$$x_0 = \text{BOS}, \quad x_t \sim p_\theta(\cdot \mid x_{<t})$$

每步的计算与前向传播完全一致：嵌入 → 注意力（KV Cache 逐步追加）→ MLP → logits → 温度缩放 → softmax → 按概率采样。采样出的 token 立即成为下一步的输入，形成自回归循环；终止条件为采样到 BOS 或达到 `block_size`。

### 温度采样的数学

$$p_i = \frac{\exp(z_i / T)}{\sum_j \exp(z_j / T)}$$

- $T \to 0$：分布退化为 one-hot（argmax），确定性与多样性归零
- $T = 1$：恢复模型学到的原始分布
- $T > 1$：熵增大，长尾 token 被更多采出

温度缩放不改变 token 的相对排序，只改变分布的锐度——因此它调节的是**探索/利用**平衡，而非"更好的答案"。生产系统常叠加 top-k / top-p（核采样）截断，过滤掉低温下的长尾噪声。

### 推理与训练的关键差异

| 维度 | 训练 | 推理 |
|------|------|------|
| 参数 | 可更新 | 冻结 |
| 目标 | 最小化交叉熵 | 从 $p_\theta$ 采样 |
| teacher forcing | 输入为真实 token | 输入为自己生成的 token |
| 错误累积 | 无 | 有（一步走偏，后续全偏）|
| 随机性 | 无（确定性前向）| 有（采样引入）|

**exposure bias**：训练时模型总看"标准答案"，推理时却要吃自己的输出，误差会滚雪球。这是所有自回归模型的共性弱点，生产中通过 RLHF 阶段让模型接触自身生成内容来缓解。

### 从名字生成到 ChatGPT

把"名字"换成"对话"，整个推理循环一字不改：系统提示词 + 用户消息 + 助手回复，都是序列中的 token；ChatGPT 的每个回复，本质上也是从 $p_\theta$ 里一个 token 一个 token 采样出来的"统计文档补全"。区别只在于规模、分词、以及后训练把分布塑造成了"乐于助人"的形状。
