# 上下文管理：Agent 的注意力预算

> 本文是 Agent 外壳八大组件系列第 4 篇。总览见 [20260923-1429-Agent本质.md](20260923-1429-Agent本质.md)。

---

## 一、一句话回答

**上下文工程（Context Engineering）是在模型每一步推理时，把"正确的信息"在"正确的时机"交给模型——写入、选择、压缩、隔离四类策略。** Anthropic 的定义是："在大模型推理时**策展与维护最优 token 集合**的策略集合"。注意"策展"这个词——是主动管理，不是"写好一段提示词就完事"。

它为什么是 2026 年 Agent 性能提升的隐藏杠杆？因为：**模型不推理你的"意图"，它只推理它实际看到的 token。措辞再好、上下文配错就翻车；措辞一般、上下文精准反而稳。**

---

## 二、为什么必须管理？——注意力是稀缺资源

三个被反复验证的事实：

1. **Databricks 研究**：主流大模型超过约 **32k token** 后效果显著衰减。200k 的窗口不是让你装满再用的。
2. **注意力预算**：上下文是边际收益递减的稀缺资源——每引入一个新 token，都会消耗模型的"注意力预算"。
3. **典型翻车**：一个采购审批 Agent 跑到第 12 步时，第 3 步返回的 5 万 token 原始 JSON 还堆在历史里——注意力被稀释光，模型忘掉目标、忽略约束、开始编造数据。

**比喻**：模型是"鱼的记忆，而且是被水呛过的那种"；上下文是一张办公桌——东西都在眼前，但堆满了就找不到此刻真正需要的那一页。Prompt Engineering 是把考题写清楚，Context Engineering 是**设计整个考场**。

## 三、四大策略：Write / Select / Compress / Isolate

LangChain 把业界主流手法归纳为四类，构成一条完整流水线：

### 1. Write（写入）——解决"存"的问题
把重要状态写到上下文窗口**之外**，供后续取用。Scratchpad（草稿本）、progress.md、decisions.md、跨会话记忆。**不要指望模型永远记得**——对恢复、审计、下一步决策重要的信息，就应该写到外部。

### 2. Select（选择）——解决"找"的问题
每一步只拉回相关信息。代码审查 Agent 不该读整个仓库——先看 PR diff，再按需展开相关文件。Claude Code 用 CLAUDE.md 固定拉入项目规范；更复杂的是 RAG 向量检索 + 重排序。

### 3. Compress（压缩）——解决"挤"的问题
只保留完成任务必需的 token。**不是简单删短**——好的压缩要保留：当前目标、已完成动作、关键事实、未解决问题、决策理由。Claude Code 的做法：上下文用到 95% 时自动触发 auto-compact，对整个交互轨迹做摘要，保留架构决策和未解决 bug，丢弃冗余工具输出。

### 4. Isolate（隔离）——解决"分"的问题
把上下文拆到独立空间。最常见是多 Agent 架构：主 Agent 统筹，子 Agent 各自在干净窗口里执行任务，消耗几万 token 完成一次搜索，只返回一两千 token 的精炼摘要。Anthropic 实验显示隔离上下文的多 Agent 优于单 Agent——**代价是 token 消耗最高可达聊天模式的 15 倍**。

一句话记住：**该常驻的常驻、该按需加载的按需加载、该压缩的压缩、该隔离的隔离。**

## 四、为什么说"一半是算法，一半是流程"

- **算法部分**：向量检索、重排序、摘要模型、知识图谱（Mem0 的 2026 年报告：纯向量检索只能告诉 AI"用户提到过 Python"，图记忆能推理出"用户在 XX 公司用 Python 做数据管道、正从 Spark 迁移到 dbt"——信息密度差一个量级）。
- **流程部分**：什么时候触发压缩、什么信息升级为长期记忆、Token 预算怎么分配、稳定前缀如何利用 KV Cache 降延迟降成本。这些是工程决策，不是模型能力。

---

## 五、常见坑

1. **压缩把关键证据压没了**：省 token 省掉了后面要用的事实。
2. **Prompt Injection 是上下文安全的核心威胁**：Agent 读网页、文件、邮件时，外部内容可能夹带恶意指令。必须做到**外部数据 ≠ 系统指令**（来源标记、指令与数据分离）。
3. **隔离优于事后压缩**：对会产生大量中间信息的任务，让子 Agent 在源头消化噪声，比事后清理主上下文更干净。
4. **窗口大了就不管了**：大窗口只是让你死得更晚，衰减规律不会消失。
