# microgpt 项目分析

## 一、项目概述

microgpt 是 Andrej Karpathy 的教育性艺术项目——一个**仅约 200 行核心代码、零第三方依赖**的纯 Python 文件，完整实现了 GPT 模型的训练与推理全流程。本仓库是该项目的中文学习版，包含：

- [microgpt.py](../microgpt.py)：Karpathy 原作的**中文详细注释版**（817 行，含大量教学注释）
- [README.md](../README.md)：Karpathy 博客的中文翻译，逐模块讲解代码
- `input.txt`：训练数据集（约 32,000 个英文名字，每行一个）
- 4 个交互式 HTML 演示页：`attention_demo.html`、`autograd_demo.html`、`rmsnorm_demo.html`、`softmax_demo.html`（配套核心概念的可视化教学）
- 演示图与 PPT：`microgpt_blog_image.jpg`、`microgpt_presentation.pptx`

## 二、技术栈

- **语言**：纯 Python，仅使用标准库（`os`、`math`、`random`），无需 pip 安装任何依赖
- **无深度学习框架**：不使用 PyTorch/TensorFlow，自动微分、优化器、模型全部手写
- **运行方式**：`python microgpt.py`，笔记本上约 1 分钟跑完训练

## 三、核心模块解析（microgpt.py）

代码按 7 个部分组织，数据流为：**数据集 → 分词器 → 自动微分 → 参数 → 模型 → 训练 → 推理**。

### 1. 数据集（第1部分）
- 缺少 `input.txt` 时自动从 GitHub（makemore/names.txt）下载 32,033 个英文名字
- 每个名字是一个"文档"，随机打乱训练顺序

### 2. 分词器（第2部分）
- **字符级分词**：26 个小写字母 a→z 分别映射为 id 0~25
- 额外引入 **BOS**（id=26）作为序列开始/结束标记，词汇表大小为 27

### 3. 自动微分引擎（第3部分，核心）
- `Value` 类包装标量数字，实现"智能数字"：
  - 支持 `+`、`*`、`**`、`log`、`exp`、`relu` 六种基本运算（前向计算 + 记录局部梯度）
  - 通过运算符重载支持完整的四则运算
- `backward()`：深度优先搜索构建拓扑排序，逆序应用链式法则 `∂L/∂child += ∂v/∂child × ∂L/∂v`
- 使用 `__slots__` 优化海量 Value 对象的内存占用
- 等价于 PyTorch 的 `loss.backward()`，只是作用于标量而非张量

### 4. 模型参数（第4部分）
- 超参数极小：`n_embd=16`、`n_head=4`、`n_layer=1`、`block_size=16`
- 总参数量 **4,192 个**（对比：GPT-2 有 16 亿，GPT-4 有数千亿）
- 参数组织为 `state_dict`：wte（词嵌入 27×16）、wpe（位置嵌入 16×16）、注意力 QKVO（各 16×16）、MLP（16↔64）、lm_head（27×16）
- 高斯分布 `N(0, 0.08²)` 随机初始化，打破对称性

### 5. 模型架构（第5部分）
GPT-2 架构的简化版，遵循现代简化约定：
- **RMSNorm** 替代 LayerNorm（去掉均值中心化，更简洁）
- **ReLU** 替代 GeLU
- 去掉所有偏置（bias）
- 单 token 前向传播，显式维护 **KV Cache**（缓存的 K/V 是计算图中的活跃 Value 节点，因此**训练时也通过缓存反向传播**——这是该实现的一个独特之处）
- 结构：嵌入 → [注意力（token 间"通信"）+ 残差] → [MLP（token 内"思考"）+ 残差] → logits

### 6. 训练循环（第6部分）
- 每步取一个名字，BOS 包裹（`emma → [BOS,e,m,m,a,BOS]`），逐位置预测下一 token
- 损失为交叉熵：`-log p(正确下一个字符)`，对序列取平均
- **手写 Adam 优化器**：一阶矩 m（动量）、二阶矩 v（自适应步长）、偏差修正、学习率线性衰减（0.01 → 0）
- 训练 1,000 步，loss 从约 3.3（`-log(1/27)` 随机水平）降至约 2.37

### 7. 推理生成（第7部分）
- 自回归采样：从 BOS 开始，softmax 后按概率随机采样下一字符，循环直到采样到 BOS 或达到最大长度
- **温度参数** `temperature=0.5`：logits 除以温度控制分布尖锐度（低温度更保守，高温度更随机）
- 生成 20 个"幻觉"出的新名字（如 kamon、karia），与 ChatGPT 的编造现象同源

## 四、项目特色与价值

1. **完整算法闭环**：数据、分词、自动微分、Transformer、优化器、训练、推理一应俱全，是理解 LLM 内部机制的最佳入门教材之一
2. **中文注释极其详尽**：原代码每一段都配了生活化类比（收音机旋钮、传话游戏、合唱团等），适合无机器学习背景的 Python 初学者
3. **配套教学资源丰富**：README 全文翻译 + 4 个 HTML 交互演示 + PPT，形成完整学习体系
4. **可复现**：固定随机种子（`random.seed(42)`），每次运行结果一致

## 五、可改进方向

- **性能**：纯 Python 标量运算极慢（社区实测去掉 autograd、手写反向传播可从 40s 降到 5s；用 NumPy 向量化会更快）
- **工程化**：可增加命令行参数（步数、温度、模型大小）、训练损失可视化
- **扩展实验**：更换数据集（城市名、古诗等）、增大模型规模，验证学习曲线
- **文档**：HTML 演示页与代码模块的对应关系可在 README 中补充索引

## 六、总结

> "这个文件就是完整的算法。其他一切都只是为了效率。" —— Karpathy

microgpt 用最小的代码量呈现了从 ChatGPT 到 GPT-4 共享的核心算法本质：预测下一个 token 的循环。理解了这个 200 行脚本，就理解了大语言模型的算法精髓；从它到生产级 LLM 的差距，全部在于工程效率与规模，而非算法本身。
