# Agent 真的只是"提示词 + md 文档"吗？

> 系列阅读地图：接 [20260923-1417-AI基础设施.md](20260923-1417-AI基础设施.md) 和 [20260923-1422-训推差异.md](20260923-1422-训推差异.md)，这篇聊 AI Infra 之上的一层——Agent。
>
> 你的原话是："Agent 就是在大模型外面加了一些提示词、一些 md 文档。"下面用互联网上的证据反驳这个说法。**先承认你说对的部分，再逐条反驳"只是"两个字。**

---

## 一、先承认：你说对了一半

诚实地说，这个观点有两块是对的：

1. **模型仍然是地基。** Agent 的"智力"完全来自大模型，外面那圈东西再花哨，也变不出模型没有的能力。这与我们之前聊过的"参数量 = 房间面积"是同一个道理——Agent 是在房间里的活动方式，不是扩建房间。
2. **md 文档确实是提示词的一种形态。** Agent Skills（SKILL.md）、系统提示词、规则文件，本质都是"喂给模型的 token"。这点你没说错。

**但你漏算了中间那一大层。** 说"Agent = 模型 + 提示词"，就像说"公司 = 老板 + 员工手册"——手册确实是公司的一部分，但公司能运转靠的是工位、财务系统、审批流程、考勤、会议室和前台。下面逐条反驳。

---

## 二、反驳一：同样的模型，换个"外壳"，成绩差近 3 倍

这是最硬的一条证据。2026 年的 AI 工程圈流传着一个实验（GPT-5.6 Sol 长程评测）：

- **同一个模型**，在标准 harness（Agent 外壳）下，长程任务成功率 **13.3%**
- 加入更好的上下文压缩、保留推理等系统改造后，**38.3%**

**模型一个字没变，成绩翻了近 3 倍。** 如果 Agent 真的"只是提示词"，这种差距不可能出现。决定成败的不是模型有多聪明，而是**外面的系统在每一步让它看到什么、允许它做什么、错了怎么救**。

类比：同一位 F1 车手（模型），开后勤拉胯的车队 vs 顶级车队，成绩天差地别。车手天赋是必要条件，但不是胜负手。

---

## 三、反驳二：生产环境的失败，恰恰不赖提示词

LangChain 对真实生产环境的统计结论：

> **Agent 失败的主要原因不是提示词写得不好，而是上下文不完整、不相关或信息密度太低。**

典型翻车现场：一个企业采购审批 Agent，第 1 步查库存、第 5 步查预算、第 12 步写报告。到第 12 步时，如果第 3 步那次工具调用返回的 5 万 token 原始 JSON 还堆在历史里，**模型的注意力早被稀释光了**——它会忘掉目标、忽略约束、开始编造数据。

Databricks 的研究补充了另一半：主流大模型超过约 **32k token** 后效果显著衰减——200k 的窗口不是让你装满再用的。

所以业界的共识已经变了：

- **Prompt Engineering（提示词工程）**：把考题写清楚——只是最内层
- **Context Engineering（上下文工程）**：设计整个考场——带什么资料、允许翻哪页、时间怎么分
- **Harness Engineering（外壳工程）**：整个考试系统——监考、补考、作弊检测

Anthropic 的定义是："上下文工程是在模型推理时**策展和维护最优 token 集合**的策略集合"。注意"策展"这个词——是主动管理，不是"写好一段话就完事"。

2026 年 DataHub 的调研数据：**82% 的 IT 与数据负责人认为"仅靠提示词工程已不足"，95% 认同上下文工程是 Agent 规模化的必要条件。**

---

## 四、反驳三：那圈"外壳"里装的东西，比你想的多得多

拆开一个生产级 Agent 的外壳看看，md 文档只是其中一格：

| 组件 | 干什么 | 是"提示词"吗？ |
|---|---|---|
| **Agent Loop（执行循环）** | 思考→调工具→观察→再思考的循环，跑几十上百轮 | 不是，是程序逻辑（→[执行循环](20260923-1433-执行循环.md)） |
| **工具调用（Tool Use / MCP）** | 读写文件、执行代码、查数据库、操作浏览器——从"能想"到"能做" | 不是，是真实执行的系统接口（→[工具调用](20260923-1433-工具调用.md)） |
| **记忆分层** | 短期记忆（会话内）+ 长期记忆（向量库）+ 任务状态持久化 | 不是，是数据库工程（→[记忆分层](20260923-1433-记忆分层.md)） |
| **上下文管理** | 写入、选择、压缩、隔离四类策略，Token 预算制 | 不完全是，一半是算法一半是流程（→[上下文管理](20260923-1433-上下文管理.md)） |
| **编排（Orchestration）** | 超时处理、重试退避、循环检测、多 Agent 协作、并行调度 | 不是，是分布式系统问题（→[Agent编排](20260923-1433-Agent编排.md)） |
| **权限与安全** | 危险操作前二次确认、沙箱隔离、密钥管理 | 不是，是安全工程（→[权限安全](20260923-1433-权限安全.md)） |
| **验证与恢复** | 测试结果回读、失败恢复、错误处理 | 不是，是可靠性工程（→[验证恢复](20260923-1433-验证恢复.md)） |
| **Skills / md 文档** | 结构化的能力声明，告诉模型"你会什么、怎么用" | **是，这一格确实是提示词**（→[Skills技能](20260923-1433-Skills技能.md)） |

没有超时机制和循环检测的 Agent，遇到失败任务会**无限重试同一个步骤，把 Token 和钱一起烧光**——这是编排问题，写再多提示词也救不了。

**关键洞察：大模型 API 本身是无状态的。** 它天生只会"看一眼文字、回一段话"。让模型能记住上一步、能操作真实世界、能连续工作几小时——**全靠外面那圈系统把它们"缝"出来。** 外壳不是装饰，是把"会说话的脑子"变成"能干活的员工"的全部工程量。

---

## 五、反驳四：md 文档恰恰是这套系统里"最被低估"的部分

反过来打：就算聚焦在 md 文档上，"加了些文档"这个说法也太小瞧它了。

2025 年 Skills 封装成为 Agent 里程碑，它解决的是一个精确的工程问题：**模型参数里没有的知识和流程，怎么在不重训、不微调的前提下注入**。一篇 SKILL.md 是结构化的能力声明——什么时候触发、步骤是什么、坑在哪里——本质是**把"教人做事的经验文档"变成模型的可执行流程**。

这套打法的力学：Anthropic 自己的说法是，一个模型写得再好，没有好的上下文和流程，长任务也跑不完；有了正确的上下文管理，同一个模型能完成的工作量成倍增加。**文档改变行为，因为它改变的是模型每一轮"看到的世界"。**

回忆我们之前聊过的核心认知：**预训练决定模型有多聪明，后训练决定模型怎么说话**。现在可以加一句：**外壳决定模型能干多少活**。三层是并列的工程体系，不是"提示词"一个词能概括的。

---

## 六、一个更准确的公式

把你的说法修正一下：

> ~~Agent = 大模型 + 一些提示词 + 一些 md 文档~~
>
> **Agent = 大模型（大脑）+ 执行循环（心跳）+ 工具（手脚）+ 记忆（笔记本）+ 上下文工程（每一眼看到什么）+ 编排与恢复（摔倒了爬起来）+ 提示词与 Skills（岗位说明书）**

**比喻**：模型是刚毕业的高材生——聪明但没记性、没工具、没流程。Agent 系统是公司给他的全部配套：工位和电脑（工具）、例会和周报（循环与记忆）、SOP 手册（Skills）、导师随时递到他桌上的关键资料（上下文工程）、审批流和容错机制（编排）。**手册只是其中一张纸，但没有人会说公司 = 一叠手册。**

---

## 七、诚实的边界：反驳之外，你的直觉指向一个真问题

为了公平，也要说：这个质疑背后藏着一个真实的行业隐忧——

1. **套壳产品确实泛滥**：很多"Agent 产品"真的只是系统提示词 + 一个聊天框，没有工具、没有记忆、没有验证。对这类产品，你的批评完全成立。
2. **模型在吞噬外壳**：模型每代升级，都会把上一代外壳里的技巧内部化（长上下文内化了 RAG 的一部分，工具使用内化成原生能力）。外壳是在跟模型赛跑。
3. **2026 年的共识**：从最简单的模式起步，顺序流水线能解决的事不要上多 Agent——**行业里最常见的失败恰恰是过度工程化**。外壳不是越厚越好。

但"有些 Agent 是套壳"和"Agent 只是套壳"是两个命题。前者是对的，后者被上面四条证据否决了。

---

## 八、回到 microgpt：一个最小的"外壳"实验

microgpt 本身没有 Agent，但 generate() 的自回归循环就是 Agent Loop 的雏形——**每生成一个 token，把新 token 拼回输入，再生成下一个**。Agent Loop 只是把"生成下一个 token"换成了"生成下一步行动"，把"拼回输入"换成了"把工具结果拼回上下文"。

**Agent 没有任何魔法，它就是自回归循环 + 工具 + 记忆管理。** 但正是这三样"大模型外面"的东西，决定同一个模型是只会聊天，还是能替你写代码、查资料、跑测试。
