# Skills：md 文档的工程化逆袭

> 本文是 Agent 外壳八大组件系列第 8 篇（收尾）。总览见 [20260923-1429-Agent本质.md](20260923-1429-Agent本质.md)。
>
> 这一格是我们唯一承认"确实是提示词"的组件——但看完这篇你会发现，它远比"提示词"三个字有含金量。

---

## 一、一句话回答

**Agent Skills 是结构化的能力声明：把一类任务的流程、规则、参考资料和脚本打包在一起（核心是一个 SKILL.md），让 Agent 需要时再使用。** 它解决一个精确的工程问题：**模型参数里没有的知识和流程，怎么在不重训、不微调的前提下注入。**

你正在看的这个项目里就有一个活例子：`.qoder/skills/write-md-doc/SKILL.md`——它定义了"写文档 → 写入 docs/ → 按时间戳命名"这套流程，我每次执行写文档任务都会先加载它。

---

## 二、结构：一个 Skill 目录长什么样

```
my-skill/
├── SKILL.md          # 必须：元数据(YAML) + 指令正文
├── scripts/          # 可选：可执行脚本
├── references/       # 可选：深度参考文档
└── assets/           # 可选：模板、示例
```

SKILL.md 开头的 YAML 块必填 `name`（名称）和 `description`（描述）。**description 写得好不好，直接决定技能会不会被触发**——因为模型就靠这一句话判断"这个任务该不该用这个技能"。

## 三、核心机制：渐进式披露（Progressive Disclosure）

这是 Skills 最有含金量的设计。先看它解决的问题：

**假设你有 50 个技能，每个技能完整说明平均 800 token。全部塞进系统提示 = 4 万 token 打底**——还没开始干活，上下文就被吃掉一大半，成本飙升，模型注意力被无关说明稀释得一干二净。

### 三层加载

| 层级 | 加载什么 | 占用 |
|---|---|---|
| **1. 发现层** | 所有技能的 name + description（"书的目录"） | 每条几十 token，常驻系统提示 |
| **2. 决策层** | 任务命中某个技能时，才读它的完整 SKILL.md | 按需，一次一两个 |
| **3. 执行层** | 真正执行时才读 references/ 或跑 scripts/ | 最深处，用时才碰 |

**比喻**：新员工入职，公司不会第一天把所有制度、系统手册、历史项目文档全丢给他，而是：先告诉他有哪些系统 → 要处理某类任务时再给对应 SOP → 执行到具体步骤才打开字段说明和模板。渐进式披露的本质是**"减少当前阶段不需要的信息"**，而不是简单地减少信息。

效果：把模型从"死记硬背的背题家"变成"会查手册的聪明人"。

## 四、Skills 与相邻概念的区别

| 概念 | 回答的问题 | 关系 |
|---|---|---|
| **提示词** | 这一句话怎么写 | Skills 的元数据和正文本质是提示词，但是**结构化、可分层加载的** |
| **MCP 工具** | 怎么执行动作 | Skills 可以指导模型"何时、如何"使用工具（见[工具调用](20260923-1433-工具调用.md)） |
| **微调** | 怎么把能力烧进参数 | Skills 是外挂的、可热更新、可版本管理的 |
| **RAG** | 怎么检索知识 | Skills 是"任务流程知识"，RAG 是"事实知识" |

**关键理解**：Skill 不是提示词的堆砌，而是**结构化知识单元**——它把"教人做事的经验文档"变成模型的可执行流程。2026 年它已发展成开放标准（agentskills.io），Google 官方开源了 skills 仓库，同一个 Skill 可跨 Claude Code、Cursor、Copilot 等工具使用。

## 五、为什么 md 文档"被低估"了

回到总览篇里的争议——"Agent 就是加了一些 md 文档"。现在可以给出完整回应：

1. **md 文档改变行为，因为它改变的是模型每一轮"看到的世界"**——这正是上下文工程（见[上下文管理](20260923-1433-上下文管理.md)）的 Select 策略的工程化样本
2. **渐进式披露本身是精巧的系统设计**：三层加载、按需注入、token 预算控制
3. **Skills 承载的是组织的工程经验**：什么时候触发、步骤是什么、坑在哪里——这是把"老师傅的手感"变成"可复制的 SOP"
4. **它与其他七个组件协同**：没有执行循环，Skill 没有运行时机；没有工具，Skill 只能纸上谈兵；没有上下文管理，Skill 会撑爆窗口

**所以正确的说法是：md 文档是这套系统里最"便宜"的组件，但不是"简单"的组件。**

## 六、常见坑

1. **description 写得含糊**：模型判断不出来该不该触发——技能等于不存在。
2. **正文写成散文**：没有明确的触发条件、步骤和边界，模型读了也不知怎么执行。
3. **技能堆太多不治理**：只加不删，发现层目录越来越长，选择准确率下降。
4. **把 Skills 当万能药**：需要精确执行的逻辑应该写成脚本（scripts/），而不是用自然语言描述"请仔细一点"。
