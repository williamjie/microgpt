# 工具调用：从"能想"到"能做"

> 本文是 Agent 外壳八大组件系列第 2 篇。总览见 [20260923-1429-Agent本质.md](20260923-1429-Agent本质.md)。

---

## 一、一句话回答

**工具调用让模型从"只能聊"变成"能动手"：读写文件、执行代码、查数据库、操作浏览器。** ChatGPT 只有一颗大脑，它的世界终结于对话框；没有工具调用能力的 AI，再聪明也只能"想"，不能"做"。

这块涉及两个常被混淆的概念：**Function Calling** 和 **MCP**。先说结论：**它们不是同一层的东西，不存在谁替代谁**。

---

## 二、Function Calling：模型的"点单能力"

Function Calling 是大模型 API 内置的一种**决策能力**：

- 你用 JSON Schema 把函数的名称、参数、描述告诉模型
- 模型在对话中自主判断"要不要调、调哪个、传什么参数"
- 模型返回**结构化的调用意图**——注意：**模型只负责"点单"，不负责"做菜"**，真正执行函数的是你应用代码里的逻辑

一次完整调用是五步往返：模型表达意图 → 应用执行 → 结果回填上下文 → 模型继续推理。

---

## 三、MCP：AI 世界的 USB-C

**MCP（Model Context Protocol，模型上下文协议）** 是 Anthropic 于 2024 年 11 月开源的标准化协议，解决"应用如何发现和执行具体工具"的问题——让工具可以**一次开发、全网 AI 通用**。

### Function Calling 与 MCP 的关系（最好记的比喻）

> **Function Calling = 手机语音助手**：知道该调哪个 App、传什么指令，但只能控制本机应用。
> **MCP = 蓝牙协议**：定义设备之间如何连接通信，让任何手机都能连任何耳机。

用语音助手说"播放音乐"：语音助手（Function Calling）识别意图，通过蓝牙（MCP）把指令发给音箱执行。另一个常用比喻：Function Calling 给电器规定了电压（220V），但各国插头形状不同；MCP 统一了插头形状——USB-C，走到哪都能插。

### 核心对比

| 维度 | Function Calling | MCP |
|---|---|---|
| 本质 | 大模型 API 内置的决策能力 | 跨模型的标准化通信协议 |
| 所属层级 | 模型层（LLM ↔ 应用后端） | 应用层（应用后端 ↔ 工具服务器） |
| 模型依赖 | 深度绑定厂商格式 | 模型无关，一次封装处处通用 |
| 工具发现 | 每次请求手动传入工具定义 | `tools/list` 动态发现，支持热插拔 |
| 安全管控 | 依赖应用层自行实现 | 协议内置权限协商、审批机制 |

### 一条完整的 MCP 链路

Host 加载 Server → Server 宣告能力（工具列表 + JSON Schema）→ Agent 决定调用 → Client 转发请求（JSON-RPC 2.0）→ Server 执行 → 结果返回 → Agent 生成回答。

MCP Server 对外暴露三类东西，安全等级不同：

- **Tools（工具）**：可执行、有副作用的动作（写文件、调 API、删数据）——高风险，可强制人工审批
- **Resources（资源）**：只读数据源（文件内容、表结构、文档）——只读不需二次确认
- **Prompts（提示模板）**：可复用的预置提示词，实现模板跨应用共享

## 四、为什么说"这一格不是提示词"

关键洞察：**模型输出的只是一段 JSON 意图，真正改变世界的是外部程序**。读文件的是文件系统、跑代码的是解释器、转账的是银行 API。工具调用是把大模型接到真实世界的一套**系统接口**——它有进程隔离、有认证鉴权、有错误处理，是正经的系统工程，不是"多写几句话"。

这直接决定了后面两篇的内容：工具能触碰真实世界，所以需要[权限与安全](20260923-1433-权限安全.md)；工具会失败，所以需要[验证与恢复](20260923-1433-验证恢复.md)。

---

## 五、常见坑

1. **层级混淆**：以为 MCP 是 Function Calling 的升级版可以取代它——实际上 Agent 内部依然用 Function Calling 表达意图，用 MCP 跟外部工具交流。"用 Function Calling 思考，用 MCP 说话"。
2. **权限全开**：把所有工具挂载、API Key 全部注入，等于把大门钥匙交给容易相信陌生人的前台。
3. **工具描述写得差**：模型靠描述决定调不调、怎么调，描述含糊 = 调用瞎猜。
