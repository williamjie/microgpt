## 0. 摘要（TL;DR）

AgentScope Java 2.0 相对 1.0.8 不是小版本迭代，而是一次**架构级重构**，可概括为三句话：

1. **扩展包化**：模型提供方（DashScope / OpenAI / Gemini / Anthropic / Ollama）从 `agentscope-core` 移出到 `agentscope-extensions-model-*`；A2A / Nacos 等能力也从单体 starter 拆成独立扩展，全家桶时代结束。
2. **状态外置**：`ReActAgent` 实例完全无状态，会话历史放 `AgentState.getContext()`，持久化统一走 `AgentStateStore`，按 `(userId, sessionId)` 自动存取。
3. **中间件化**：Hook 事件机制整包标记 `@Deprecated(forRemoval=true)`，官方推荐用 `Middleware`（五阶段）承接；事件消费从 `stream()` 转向 `streamEvents()`（28 种类型化事件）。

对 1.0.8 老项目：**Part A 共 8 类必迁项，不迁移则编译失败或运行抛异常；Part B 共 6 类 API 已建议迁移，可缓但不宜久拖。**官方同时保留 `LegacyHookDispatcher`、`ToolkitState(legacy)` 等兼容桥，降低一次性迁移成本。

## 1. 调研背景与信息来源

**背景**：以多智能体旅游规划系统为样本（ManagerAgent 调度 + RouteMakingAgent / TripPlannerAgent / SuggestSightAgent 协作，A2A 协议 + Nacos 服务发现组网，DashScope/Qwen 模型，百度地图 MCP 工具），评估从 AgentScope Java 1.0.8 升级到 2.0 的成本与收益。

**信息来源**（三类交叉验证）：

| 来源 | 性质 | 用途 |
| --- | --- | --- |
| 官方 1.x→2.0 迁移指南（java.agentscope.io） | 权威，按"必迁 / 建议迁移"分级 | 变化清单的基准骨架 |
| 掘金《逐行拆解 AgentScope 1.0.8》（9i编程） | 1.0.8 全量实战代码 | 还原 1.x 侧真实用法 |
| 掘金《从 AgentScope 1.0.8 升级到 2.0》（9i编程） | 2.0 升级实战 | 验证迁移路径与真实坑位 |

> 方法说明：以官方迁移指南为骨架，用两篇实战文章对每个变化点做"双向确认"——1.x 侧怎么用、2.0 侧换成什么、过程中踩了什么坑。两处相互印证才写入本文。

## 2. 版本脉络与架构定位

| 版本 | 定位 |
| --- | --- |
| 1.0.8 | 1.x 末班车：`agentscope-spring-boot-starter` 全家桶，`io.agentscope.core.*` 单体包 |
| 2.0 | 架构级重构：core 只留契约，provider / a2a / nacos / harness 等拆为扩展模块 |
| 2.0.x | 持续迭代（命令注册、Hook 适配、legacy 会话状态兼容等修复） |

**架构对比（一句话版）**：

| 维度 | 1.0.8 | 2.0 |
| --- | --- | --- |
| Agent 状态 | 实例持有当前会话状态（`getCurrentSessionId()` 等） | 完全无状态，`RuntimeContext` 携带 userId/sessionId |
| 模型集成 | core 内置 5 家 ChatModel | core 只留 `Model`/`ChatModelBase`/`Formatter`/`ModelRegistry` 契约 |
| 任务分解 | `PlanNotebook`（结构化 Plan + SubTask + 8 工具 + 状态机） | Plan Mode（markdown 计划 + 3 工具）/ TaskList（TodoTools） |
| 扩展机制 | Hook 事件 + `Memory` + `SkillBox` | Middleware 五阶段 + `AgentStateStore` + `skillRepository` |
| 事件消费 | `stream()` 重载族 + chunk 事件 | `streamEvents()` + 28 种类型化 `AgentEvent` |

## 3. Part A · 必迁清单（不迁移 = 编译失败或运行抛异常）

官方将必迁项分为 8 类，按对 AiTripPlan 类项目的影响排序如下。

### 3.1 模型提供方移出 core（影响面最大）

```java
// 1.0.8：一个 starter 全家桶，直接 import core 里的实现
import io.agentscope.core.model.DashScopeChatModel;

// 2.0：换依赖 + 换包名
// 依赖：agentscope-extensions-model-dashscope
// （Spring Boot 项目用 agentscope-dashscope-spring-boot-starter）
import io.agentscope.extensions.model.dashscope.DashScopeChatModel;
```

| 1.x import（core 内） | 2.0 依赖 | 2.0 import |
| --- | --- | --- |
| `io.agentscope.core.model.OpenAIChatModel` | `agentscope-extensions-model-openai` | `io.agentscope.extensions.model.openai.OpenAIChatModel` |
| `io.agentscope.core.model.DashScopeChatModel` | `agentscope-extensions-model-dashscope` | `io.agentscope.extensions.model.dashscope.DashScopeChatModel` |
| `io.agentscope.core.model.GeminiChatModel` | `...-model-gemini` | `io.agentscope.extensions.model.gemini.GeminiChatModel` |
| `io.agentscope.core.model.AnthropicChatModel` | `...-model-anthropic` | `io.agentscope.extensions.model.anthropic.AnthropicChatModel` |
| `io.agentscope.core.model.OllamaChatModel` | `...-model-ollama` | `io.agentscope.extensions.model.ollama.OllamaChatModel` |
| `io.agentscope.core.formatter.*` | 随模型扩展 | `io.agentscope.extensions.model.*.formatter.*` |
| `io.agentscope.core.credential.Credential` | 随模型扩展 | `io.agentscope.extensions.model.*.credential.Credential` |

`ModelRegistry` 的字符串 id（如 `dashscope:qwen-plus`）在 2.0 仍可用，但对应扩展模块必须在 classpath 上。实战文章同步确认：2.0 需按需引入 `agentscope` + `agentscope-extensions-model-dashscope` + `agentscope-extensions-nacos-a2a` + `agentscope-extensions-a2a-client` 等。

### 3.2 ReActAgent.Builder 移除的方法

| 1.x 调用 | 2.0 替代 |
| --- | --- |
| `.memory(Memory)` | `.stateStore(AgentStateStore)`：`AgentState.getContext()` 承载会话，每次 `call()` 按 `(userId, sessionId)` 自动存取 |
| `.statePersistence(StatePersistence)` | 同上，`AgentStateStore` 已吞并持久化职责 |
| `.structuredOutputReminder(...)` | 不再需要：模型层原生结构化输出（`Model.supportsNativeStructuredOutput()`，自动选原生 JSON schema 或 tool-choice 兜底） |

### 3.3 移除的包与类

| 1.x | 2.0 去向 |
| --- | --- |
| `io.agentscope.core.session.SessionManager` | builder 上 `.stateStore(...)`，每次 call 自动持久化 |
| `io.agentscope.core.pipeline.*`（Pipeline / Pipelines / SequentialPipeline / FanoutPipeline / MsgHub） | 中间件 + 子 Agent + 事件流组合编排 |
| `io.agentscope.core.model.tts.*`（14 个文件） | core 不再内置 TTS，需要则直接接上游 SDK |
| `io.agentscope.core.model.StructuredOutputReminder` | 模型层原生结构化输出 |
| `io.agentscope.core.agent.StructuredOutputCapableAgent` | 能力内联进 `ReActAgent` |
| `io.agentscope.core.hook.PendingToolRecoveryHook` | `Builder.enablePendingToolRecovery(boolean)` |
| `io.agentscope.core.hook.TTSHook` | 随 TTS 模块移除 |

### 3.4 state 包重构（编译级）

| 1.x | 2.0 |
| --- | --- |
| `AgentMetaState` | `AgentState` |
| `StateModule` | 移除（Memory / Toolkit 等不再继承它） |
| `StatePersistence` | 移除（由 `AgentStateStore` 抽象取代） |
| `ToolkitState` | 移至 `io.agentscope.core.state.legacy.ToolkitState`（仅兼容，新代码勿引用） |
| —（新增） | `Task` / `TaskContextState` / `ToolContextState` / `PlanModeContextState` / `ReadCacheEntry` |

### 3.5 PlanNotebook 整体移除（设计级变化最大）

`io.agentscope.core.plan` 整包（PlanNotebook / Plan / SubTask / PlanStorage / PlanToHint）移除，无废弃桥。

| 1.x PlanNotebook | 2.0 替代 |
| --- | --- |
| `ReActAgent.builder().planNotebook(...)` | `HarnessAgent.builder().enablePlanMode()` |
| 结构化 Plan + SubTask + 状态机（todo → in_progress → done → abandoned） | 纯 markdown 计划文件 `plans/PLAN.md` |
| 8 个工具（createPlan / reviseCurrentPlan / updateSubtaskState / finishSubtask / finishPlan / viewSubtasks / viewHistoricalPlans / recoverHistoricalPlan） | 3 个工具（plan_enter / plan_write / plan_exit） |
| 计划与执行混杂，无只读约束 | Plan Mode 只读；`plan_exit` 触发 HITL 审批后才恢复写权限 |
| `PlanToHint` 每步注入提示 | `PlanModeMiddleware` 在计划期内阻断变更类工具 |

**子任务跟踪**（1.x 项目的高频用法）在 2.0 的对应物是**任务列表**：builder 上 `.enableTaskList(true)`，注册 `TodoTools` + `TaskReminderMiddleware`。实战文章同样记录 `enablePlan()/PlanNotebook` → `enableTaskList()`。

### 3.6 Msg 校验收紧（运行期抛异常）

2.0 在构造时校验 content 与 role 的匹配：

- `USER`：仅 TextBlock / DataBlock / ImageBlock / AudioBlock / VideoBlock
- `SYSTEM`：仅 TextBlock
- `ASSISTANT`：不限制

1.x 容忍的组合（如 USER 消息携带 ToolUseBlock）在 2.0 直接抛异常。官方建议改用角色固定子类 `UserMessage` / `AssistantMessage` / `SystemMessage` / `ToolResultMessage`，在调用点显式暴露兼容性。

### 3.7 Agent 完全无状态（架构变化）

`ReActAgent` 实例不再持有任何可变"当前会话"状态，所有 per-call 状态封装在内部 `CallExecution`，经 Reactor Context 传递；单个实例可安全并发服务多 `(userId, sessionId)`。

| 1.x | 2.0 |
| --- | --- |
| `getCurrentSessionId()` / `getCurrentUserId()` | `call()` 时经 `RuntimeContext.getSessionId()` / `getUserId()` 提供 |
| `AgentBase(name, desc, checkRunning, hooks)` 构造 | `AgentBase(name, desc, hooks)`（checkRunning 不再需要，并发由 per-session 串行化保证） |
| `getState()` | `getAgentState()` 或 `getAgentState(userId, sessionId)` |
| `isCheckRunning()` / `.checkRunning(boolean)` | 仍在但已 @Deprecated（恒返回 false / 被忽略） |

### 3.8 追踪：TracerRegistry → OtelTracingMiddleware

1.x 的全局 `TracerRegistry.register(TelemetryTracer...)` 已 deprecated forRemoval；2.0 改为标准 OTel 组件：自建 `OtlpHttpSpanExporter` + `SdkTracerProvider`，`OpenTelemetrySdk.buildAndRegisterGlobal()`，再给需要埋点的 agent 装 `new OtelTracingMiddleware()`。`TelemetryTracer` 现居 `agentscope-extensions-studio` 模块（Studio 集成仍可用），但为恢复全局追踪而引入 Studio 扩展并非推荐迁移路径。

## 4. Part B · 建议迁移（@Deprecated(forRemoval=true)，下个 minor 移除）

编译运行都正常，但有明确删除时间表，建议随 Part A 一并处理：

| # | 1.x 用法 | 2.0 推荐 | 要点 |
| --- | --- | --- | --- |
| B.1 | `SkillBox` / `builder().skillBox(...)` | `builder().skillRepository(...)` 注册 `ClasspathSkillRepository` / `FileSystemSkillRepository` | 注册任一仓库后自动安装 `DynamicSkillMiddleware`，每次 call 重建技能提示词；细粒度过滤用 `.skillFilter(SkillFilter)`。实战文章侧亦为 `JarSkillRepositoryAdapter` → `ClasspathSkillRepository` |
| B.2 | `io.agentscope.core.hook` 整包（Hook / HookEvent / *Event） | `io.agentscope.core.middleware`：`MiddlewareBase` 五阶段（onAgent / onReasoning / onActing / onModelCall 洋葱型 + onSystemPrompt 管道型） | 旧 hook 经 `LegacyHookDispatcher` 仍可运行；内置 `TaskReminderMiddleware` 与 `TodoTools` 配对 |
| B.3 | `Memory` / `InMemoryMemory` / `LongTermMemory` | `AgentState.getContext()` 存会话 + `AgentStateStore` 持久化 | `Memory` 保留 `saveTo/loadFrom` 桥接旧实现；builder 链 `.stateStore(...)` 每次 call 自动存取 |
| B.4 | `stream()`（StreamableAgent 11 个重载 + AgentBase 3 + ReActAgent 4 + HarnessAgent 9，全部 forRemoval） | `streamEvents()` | 28 种类型化事件，含 HITL 流（RequireUserConfirmEvent 等）；与 Python 2.0 `reply_stream` 对齐 |
| B.5 | Knowledge / KnowledgeRetrievalTools / RAGMode / GenericRAGHook | 重写进行中 | v1 实现仍可调用，新代码不要依赖 |
| B.6 | LongTermMemory / LongTermMemoryTools 系列 | 重写进行中 | 同上 |
| B.7 | `core.tool.coding.*` / `core.tool.file.*` | **2.0 取消废弃** | 不需要工作区 / 沙箱隔离的 ReActAgent 用户，ShellCommandTool / ReadFileTool / WriteFileTool 是官方推荐直用方式；HarnessAgent 用户用 harness 自带的工作区工具 |

`streamEvents()` 示例：

```java
agent.streamEvents(new UserMessage("Hello"))
    .doOnNext(event -> {
        if (event.getType() == AgentEventType.TEXT_BLOCK_DELTA) {
            System.out.print(((TextBlockDeltaEvent) event).getDelta());
        }
    })
    .blockLast();
```

## 5. 实战迁移记录（AiTripPlan-V2：1.0.8 → 2.0）

### 5.1 文章侧实测变化对照（与官方互补）

| 1.0.8 | 2.0 | 对应官方条目 |
| --- | --- | --- |
| `enablePlan()` / `PlanNotebook`（TripPlan 构造） | `enableTaskList()` | A.5（enablePlanMode / enableTaskList(true)） |
| `JarSkillRepositoryAdapter` | `ClasspathSkillRepository` | B.1 |
| `StructuredOutputReminder` | `call(msg, Class)` 直接拿结构化结果 | A.1 |
| `io.agentscope.core.model` | `io.agentscope.extensions.model.dashscope` | A.3 |
| `agentscope-spring-boot-starter` 单依赖 | `agentscope` + `extensions-model-dashscope` + `extensions-nacos-a2a` + `extensions-a2a-client` | A.3 + 拆包 |
| 模块 `ai-common` / 包 `...ai.common.*` | 模块 `ai-core` / 包 `...ai.*` | 工程侧适配 |

### 5.2 配置变化：Nacos 三开关

2.0 把 A2A / Nacos 拆成独立扩展并**默认关闭**，老配置不生效，须显式打开：

```yaml
agentscope:
  a2a:
    enabled: true
    server:
      enabled: true
    nacos:
      enabled: true
```

### 5.3 未变的部分（降低迁移焦虑）

以下 1.0.8 用法在 2.0 基本原样沿用（个别语义有官方收紧，需留意 3.6 / 3.7）：

- `ReActAgent.builder()` 主链路
- `A2aAgent` + `NacosAgentCardResolver` 组网方式
- `Toolkit` + `@Tool` / `@ToolParam` 注解式工具注册
- 子 Agent 注册与 Prompt 组装（`PromptUtils`）
- `Msg` 基础构造与 `eventToJson` 事件转换思路（事件体系已升级为 `streamEvents`）

## 6. 踩坑实录与修复（实战文章 + 官方归因）

| # | 现象 | 根因 | 修复 |
| --- | --- | --- | --- |
| 1 | `NoSuchMethodError: LoggerContext.initCollisionMaps()` | logback 版本错配：logback-classic 1.4.14（Spring Boot 托管）vs logback-core 1.5.34（AgentScope 2.0 传递依赖引入） | pom 显式统一 logback-classic / logback-core 版本 |
| 2 | 2.0 下 Nacos 连不上、Agent Card 解析失败 | 2.0 功能拆包 + 默认关闭，1.x 单 starter 自动装配语义消失 | 显式配置三开关（见 5.2） |
| 3 | 1.0.8 多 Agent 协作 `call().block()` 抛 `No structured output in message metadata. Key '_structured_output' not found` | 阻塞式 `call()` 在多 Agent 链路中拿不到结构化输出元数据 | 改用 `stream()`（`Flux<String>`）+ `eventToJson` 转换；2.0 可直接 `call(msg, Class)` |
| 4 | `RemoteAgentTool` 返回 `Mono<String>` | 2.0 远端 Agent 工具改为响应式返回 | `stream().reduce(...)` 拼接；注意 180s 超时设置 |
| 5 | 曾出现"硬编码 Agent Card URL（http://192.168.55.1:8120）"绕过 | 工具链偷懒式绕过而非根因修复 | 作者明确反对：**跑通 ≠ 正确**，应按坑 2 根因修复 |

> 方法论备注：坑 5 是本次调研中最有价值的非技术信息——升级类任务里"先跑通再还债"极易固化，凡以硬编码绕过注册中心 / 服务发现的改动，都应判为缺陷而非进展。

## 7. 升级步骤建议（1.0.8 → 2.0 有序清单）

1. **依赖先行**：按 A.3 引入模型扩展与 A2A / Nacos 扩展，替换单体 starter；同步解决传递依赖冲突（先查 logback）。
2. **必迁 8 项**（编译期清零）：重点在 builder 状态配置（`.memory` / `.statePersistence` → `.stateStore`）、模型 import 替换、`PlanNotebook` → `enablePlanMode()` / `enableTaskList(true)`。
3. **Msg / API 语义收紧**：消息构造走 `UserMessage` 等角色子类；`getCurrentSessionId()` 等改从 `RuntimeContext` 取。
4. **建议迁移 6 项**：`SkillBox` → `skillRepository`；`Hook` → `Middleware`；`stream()` → `streamEvents()`。
5. **配置侧**：A2A / Nacos 三开关、模型 API Key 路径（Spring Boot 用 provider starter）。
6. **联调回归**：结构化输出改 `call(msg, Class)`；以"合肥 → 岳西 3 日游"多 Agent 用例做端到端回归。

## 8. 结论：如何选版本

| 选择 | 适用 | 代价 |
| --- | --- | --- |
| 留在 1.0.8 | 系统稳定、无新能力诉求 | 1.x 停止演进，长期看技术债累积 |
| 升 2.0 | 需要 Plan Mode / TaskList / 权限系统 / 工作区沙箱 / `streamEvents` 等，或产品要长期演进 | 一次性迁移成本集中在四点：依赖坐标、builder 状态配置、计划 / 任务机制、结构化输出；官方提供 `LegacyHookDispatcher` 等兼容桥 |

**总体判断**：2.0 的迁移成本对中等规模多 Agent 项目属"可承受的一次性工程"，换来的是无状态并发、中间件化扩展、细粒度权限与事件流四大结构性收益；若 `PlanNotebook` / `SkillBox` / `Hook` 用得较深，建议排一个专门迭代窗口，按第 7 节顺序推进，避免边修边升。
