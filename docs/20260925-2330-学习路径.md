## 一、这个项目是什么？

**microgpt** 是 Andrej Karpathy 的教育项目：约 200 行纯 Python、零第三方依赖，完整实现 GPT 的训练与推理。

本仓库是其中文学习版，核心资产：

| 资源 | 作用 |
|------|------|
| [microgpt.py](../microgpt.py) | 中文详细注释的完整实现（唯一需要真正读懂的代码，共 817 行，其中代码约 200 行） |
| [README.md](../README.md) | Karpathy 博客中文翻译，按模块讲解 |
| `input.txt` | 约 3.2 万个英文名字（训练集） |
| 8 个 HTML 演示 | 注意力 / 自动微分 / RMSNorm / Softmax / 分词 / 损失 / 训练步 可视化 |
| `docs/` 目录 | 本仓库已有的专题笔记（可按阶段查阅） |

**一句话**：给模型看几万个名字 → 它学会「名字长什么样」→ 编出新名字。ChatGPT 做的是同一件事，只是数据更大、模型更大。

代码主线（永远挂在脑子里）：

```text
数据 → 分词 → 自动微分 → 参数 → GPT 架构 → 训练 → 推理
```

把主线展开成 7 步流水线（第 0 周要能做到「用自己的话讲出来」）：

```text
① 读入 3.2 万个名字（input.txt）
② 每个字母编成一个数字：a=0, b=1, ..., z=25, BOS=26  ← 分词器
③ 给每个名字首尾包上 BOS："emma" → [26, e, m, m, a, 26]
④ 模型预测：给定前面的字母，下一个字母是什么（输出 27 个概率）
⑤ 模型预测得准不准，用一个数字衡量：loss  ← 损失
⑥ loss 反向告诉每个参数「该往哪调」：自动微分 + Adam  ← 训练
⑦ 训练好后，从 BOS 开始一个个采样字母，生成新名字  ← 推理
```

   - 合格线：模型可能依赖样本顺序学到虚假规律，泛化变差。

#### Day 2：分词器——把字母变成数字

- **读什么**：`microgpt.py` 第 2 部分（L70-95），约 26 行；README「分词器」章节
- **做什么**：
  1. 打开 **`tokenizer_demo.html`**，跟着交互把几个名字转成 token id
  2. 动手验证：
     ```python
     uchars = sorted(set(''.join([l.strip() for l in open('input.txt') if l.strip()])))
     BOS = len(uchars)               # 26
     vocab_size = len(uchars) + 1    # 27
     print(uchars, BOS, vocab_size)
     # 手动把 "emma" 转成 token 列表： [26, e, m, m, a, 26] 即 [26, 4, 12, 12, 0, 26]
     ```
  3. 用纸笔把 "ava" 和你自己的名字（拼音）各转一遍
- **怎么算过关**：
  - 为什么要把字母变成数字？（答：神经网络只会算数，字面上是查表：字母→它的编号）
  - BOS 为什么既当「开始」又当「结束」？（答：它就是个「边界信号」，开始和结束都用同一个信号，模型自己靠位置区分）
  - 词汇表为什么是 27？（答：26 个小写字母 + 1 个 BOS；本数据集没有大写和其他符号）

**本日自测题**：

1. 把 "ava" 写成 token id 序列。
2. 词表大小 = 字符种类数 + 1，这个 +1 是什么？
3. 为什么 BOS 的 id 是 26？

**参考答案**：
1. `[26, 0, 21, 0, 26]`（BOS-a-v-a-BOS）。
2. BOS 这个特殊的「边界符号」。
3. 26 个字母编号 0～25，BOS 追加在最后，编号为 26。

**面试复述题**：

1. 「模型为什么不能直接读字符串？」
   - 合格线：神经网络只做数值运算；分词就是「字母→编号」查表，编号再查嵌入表变成向量。
2. 「BOS 同时表示开始和结束，模型不会混淆吗？」
   - 合格线：开始和结束本质上都是「边界信号」；模型靠上下文中的位置区分。

#### Day 3：什么是「训练」——先建立直觉，不看代码

- **读什么**：README「训练循环」开头；通俗版第一站、第五站第 17～18 节
- **做什么**：打开 **`loss_demo.html`**，拖一拖、看一看，重点理解两件事：
  1. 训练 = 反复做「看前文猜下一个字母」
  2. loss = 「模型对正确答案的惊讶程度」，越小越准
- **记住这个公式的直觉**（不用会推导）：`loss = -log(正确答案的概率)`
  - 瞎猜：27 选 1，概率约 1/27，`-log(1/27) ≈ 3.3` —— 这就是初始 loss 3.3 的来历
  - 训练后：概率提上去了，loss 降到 ~2.3
- **怎么算过关**：能解释「训练就是让模型对下一个字母更不惊讶」。

**本日自测题**：

1. `loss = -log(p)` 里的 p 是什么的概率？
2. 如果词表从 27 变成 100，随机猜测的初始 loss 约是多少？
3. loss 从 3.3 降到 2.3，大致意味着什么？

**参考答案**：
1. 模型给「正确下一个字母」的概率。
2. -log(1/100) ≈ 4.61，词表越大，瞎猜基线越高。
3. 模型对正确字母的置信度明显上升（说明在学），但还没到很准的程度。

**面试复述题**：

1. 「什么是 loss？它下降说明什么？」
   - 合格线：loss 是「惊讶程度」（交叉熵）；下降 = 模型预测更贴近真实的下一个字母。
2. 「训练的本质是什么？」
   - 合格线：反复做「看前文猜下一字母」，用误差反向调参数，让惊讶越来越小。

#### Day 4：backward 怎么走的

- **读什么**：`Value.backward()` 源码（含 `build_topo`）

2. 「链式法则用一句话说明。」
   - 合格线：路径上相乘，多路径相加。

  ```text
  ① 取一个名字 → ② 前向：逐字算 logits、算 loss → ③ backward：反向填梯度
  → ④ 学习率衰减 → ⑤ Adam 更新 p.data → ⑥ p.grad = 0 清零
  ```
- **怎么算过关**：能指出代码里 `loss.backward()`、`p.data -= ...`、`p.grad = 0` 各在哪一行、干嘛用。

**本日自测题**：

1. 背出「一步训练」的 6 个动作。
2. `p.grad = 0` 应该放在哪一步之后？
3. `loss.backward()` 之后紧接着做什么？

**参考答案**：
1. 取名字 → 前向算 loss → backward → 学习率衰减 → Adam 更新参数 → 清零梯度。
2. 参数更新之后（等价于下一次 backward 之前）。
3. 按学习率用 Adam 更新每个 `p.data`，然后清零 `p.grad`。

**面试复述题**：

1. 「请完整讲一个训练 step。」
   - 合格线：六步齐全，能指出 `loss.backward()`、`p.data -=`、`p.grad = 0` 的位置。
2. 「为什么不清零梯度不行？」
   - 合格线：梯度会在 step 之间累加，更新的方向和量都错。

#### Day 2：Adam 先「当黑盒」

- **读什么**：[优化器](20260917-1124-优化器.md)；通俗版第 19 节
- **做什么**：只看两个直觉：
  1. Adam = 「会自己调速的梯度下降」（动量 + 自适应步长）
  2. 学习率衰减 = 「先大步走，接近答案时小碎步」
- **怎么算过关**：能解释 `p.data -= lr * ...` 为什么是「往损失下降的方向走」。

**本日自测题**：

1. Adam 相比普通梯度下降多了哪两样东西？
2. 本项目的学习率衰减是怎么写的？
3. 学习率设得过大可能会发生什么？

**参考答案**：
1. 动量（梯度平滑）和逐参数自适应步长。
2. 大致为 `lr = 初始lr * (1 - step/num_steps)`，线性衰减到 0。
3. 参数「步子太大」，loss 震荡甚至发散，模型学不动。

**面试复述题**：

1. 「为什么后期要把学习率调小？」
   - 合格线：接近最优解时需要小碎步精细微调；大步会在最优点附近来回跨。
2. 「Adam 是万能的吗？」
   - 合格线：不是；它有超参敏感性、可能过拟合等问题；本教学项目里只是「够用且省心」的选择。

#### Day 3：推理与温度

- **读什么**：`microgpt.py` 第 7 部分（L726-783）；通俗版第 22～23 节
- **做什么**：
  1. 记住生成循环：从 BOS 开始 → 前向得 27 个概率 → **按概率**随机采一个 → 把它接回去再预测 → 采到 BOS 或超长就停
  2. 打开 **`train_step_demo.html`**，对照上面 6 个动作走一遍
  3. 改 `temperature`（L750 处，如试 0.2 / 0.5 / 1.0 / 2.0），各跑一次，对比生成名字风格：
     - 0.2：保守、重复「安全」字母；2.0：混乱、怪名
- **怎么算过关**：能解释「温度如何影响生成」，并说清 temperature→0 是什么（贪心解码，每步选最大概率）。

**本日自测题**：

1. 生成循环什么时候停止？
2. temperature=0.5（小于 1）会让分布更尖锐还是更平滑？
3. 为什么生成过程叫「自回归」？

**参考答案**：
1. 采到 BOS，或达到 `block_size` 长度上限。
2. 更尖锐（更保守，更偏向高概率字母）。
3. 模型把自己刚生成的 token 接回输入，再预测下一个，自己推着自己滚动前进。

**面试复述题**：

1. 「temperature 是什么？调大 / 调小各会怎样？」
   - 合格线：控制采样的「随机度」；越小越保守重复，越大越发散怪异；→0 退化为贪心解码。
2. 「训练可以整段并行前向，推理为什么只能逐字生成？」
   - 合格线：推理时下文还不存在；每生成一个 token 才能确定下一步的输入。

#### Day 4～6：动手实验清单（选做 ≥ 3 项，这是理解的分水岭）

| 实验 | 改什么 | 观察什么 | 加深理解 |
|------|--------|----------|----------|
| A | `num_steps` 改为 200 / 3000 | loss 曲线与名字质量 | 训练步数 ↔ 拟合程度；A 做两个版本对比 |
| B | `n_embd` / `n_layer` 稍微加大（如 16→32） | 变慢但更好？ | 模型容量 ↔ 效果/速度 |
| C | 换数据集（城市名、宝可梦名等） | 学新分布，注意保持全小写字母 | 数据分布决定模型会什么 |
| D | 打印某个 step 的 `probs`，看下一字母信心 | 训练是否在「变准」 | 概率分布如何随训练变尖锐 |
| E | 把 `temperature` 做成命令行参数 | 工程化小练习 | 顺便练 `sys.argv` |

**实验自测题**（做完实验再答）：

1. 把 `num_steps` 从 1000 降到 200，loss 和名字质量怎么变？说明什么？
2. 换成只有 3 个不同字符的自制数据集，`vocab size` 会变成几？
3. 同一模型，temperature 0.2 / 1.0 / 2.0 各生成一轮，名字风格差异说明了什么？

**参考答案**：
1. loss 降得少、名字更乱或更短：训练不充分，分布还没学会。
2. 3 个字符 + 1 个 BOS = 4。
3. 分布形状没变，但「采样时的随机度」直接改变了探索-利用的平衡：低温保守、高温发散。

**本周面试题**：

1. 「介绍你做过的实验：改了什么、看到什么、得出结论。」
   - 合格线：一次只改一个变量、有前后对比、结论有数据支撑。
2. 「想把这个项目用到中文上，最小改动是什么？有什么坑？」
   - 合格线：换数据集、词表改为覆盖汉字；坑：词表暴涨、数据稀疏、需要更多训练步数。

**本周打卡题**：向朋友讲 5 分钟——「microgpt 和 ChatGPT 算法上相同的是什么、不同的是什么」。

> 答案提纲：相同 = 核心都是「预测下一个 token」；不同 = 数据规模、分词方式（BPE）、算力、工程（并行/显存）、后训练（SFT/RL）。详见 README「真实世界」章节。

## 七、学前术语扫盲表（遇到名词先查这里）

| 术语 | 一句话解释 |
|------|-----------|
| token | 模型眼里的「最小单位」，这里是**一个字母**；ChatGPT 是词/词块 |
| 词表（vocab） | 所有 token 的名单，本项目 27 个 |
| 参数 / 权重 | 模型里可学习的数字（约 4192 个），像收音机旋钮 |
| 前向传播 | 输入 → 算出预测 的过程 |
| 损失（loss） | 「惊讶程度」，越小越好 |
| 梯度（gradient） | 拧旋钮的方向 + 幅度 |
| 反向传播 | 从 loss 往回算每个参数的梯度 |
| 学习率（lr） | 每次拧旋钮的步长 |
| 超参数 | 人手动设定的旋钮（层数、维度、步数、温度），模型自己学不到的那部分 |
| logits / probs | 原始分数 / softmax 后的概率 |
| 嵌入（embedding） | 把编号变成一串数字向量，让「相近的东西向量相近」 |
| 注意力（Attention） | 让每个位置去「查」历史位置、按相关度取信息的机制 |
| KV cache | 推理时缓存历史 K/V，避免重复计算 |
| 残差连接 | `x = x + f(x)`，只学增量、不推翻重来 |
| 采样 | 按概率分布「抽奖」选下一个 token |
| 自回归（autoregressive） | 自己生成的内容再喂回自己，逐个往后接 |
| 幻觉（hallucination） | 模型一本正经地编不存在的内容（本项目里就是「编名字」） |

## 八、常见卡点与对策

| 卡点 | 对策 |
|------|------|
| 畏惧微积分 | 只记「局部变化率相乘＝链式法则」；先看 autograd 演示和手算例子 |
| 注意力公式晕 | 先看 `attention_demo.html`，再回代码；先理解单头再看多头循环 |
| Adam 公式多 | 先当作「聪明的梯度下降」；弄懂 `p.data -= ...` 和 `grad=0` 即可 |
| 训练太慢 / 想改大模型 | 初学保持默认超参；弄懂后再加 `num_steps` |
| 中文/别的数据效果差 | 字符集变了词汇表会变；先用全小写英文或拼音，降低变量 |
| 看不懂英文注释 | 本仓库注释已是中文；原代码只看 `microgpt.py` 即可 |
| 学了就忘 | 每天写笔记 + 每周末做小测；第四周「向朋友讲 5 分钟」是最强检验 |
| 自测题答不对 | 答错正好定位盲点，回看当天「读什么/做什么」对应段落，第二天新内容开始前补做 |
| 面试题讲不顺 | 把关键词写下来，再串成句子；连续 3 天讲不顺的主题，周末集中重读对应文档 + 演示 |
